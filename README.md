# blockmancala

三角形の盤面 × ブロックブラスト式配置 × マンカラ式配布のパズル。静的サイトのみ（バックエンド不要）。

## ルール
- 盤面は 8×8 を対角線で切った三角形。
- 下のトレイの3ピースを**指でつかんで盤面の空きへ置く**。回転なし・重力なし。3つ使い切ると補充。
- 手駒は**テトロミノ7種 + ブロックブラストの形**（1マス・直線2/3/5・3×3・2×3・小さいL(3マス)・大きいL(5マス)）。
  さらに三角の盤面に合わせた形: **斜め点線**（ななめ2・3。どのマスも別の縦・横に入り、何本ものラインの最後の1マスを同時に埋める）・
  **逆斜め**（ななめ2・3。斜辺と平行で、ラインの斜辺側の端をまとめて埋める）・**階段ヘビ**（W型5マス）・**十字**（5マス）。
  21種類×全向き＝46種。種類ごとの出やすさは `src/core/pieces.js` の重み（テトロミノ各1、1マスは0.5、3×3は0.6 など）。
  各枠 **約10%** の確率で、今の盤面のどこかに置けば発動が起きる形が選ばれる（`CHAIN_PIECE_RATE`）。
  さらに各枠 **約30%** で、**今の盤面の穴・凹みに気持ちよくはまる形**が選ばれる（`FIT_PIECE_RATE`）。列を消すのとは別に
  「空いている所にぴったり入れたい・凹みを埋めて四角くそろえたい」気持ちに応えるため。はまり方（`Sim.fitOf`）は3つ:
  - **ぴったり**（perfect）: 置くとまわりの空きに1つも接しない＝ブロックに囲まれた穴をちょうど埋める
  - **長方形**（rect）: 置くと、形がまるごと入るすきまの無い長方形（縦横2マス以上・6マス以上・前からのブロック2個以上）ができる
  - **凹み**（dent）: ブロックに接し、ふさがる辺（ブロック + 盤面の外）が空きに接する辺より多い
  選ばれやすさは ぴったり 8 : 長方形 6 : 凹み 1（× 形のマス数。`FIT_WEIGHTS`）
- 新しい3つの決め方（埋まり具合 = 「連鎖が終わった盤面に残せる最大 28 個」に対する割合。縦横16本すべてに空きが要るので、
  36マスのうち最低8マスは必ず空く）:
  - 埋まり具合に関係なく、**必ず詰まない置き方が1つ以上ある**組み合わせ（連鎖込みの探索で確認）
  - **置き方の数**（3つとも置き終えた盤面の種類。順番を入れ替えただけのものは1通り）を、埋まり具合に比例して桁で減らす。
    目標 = 300^(1 - 埋まり具合)（空 300 → 半分 17 → 8割 3 → 満杯 1）。候補を抽選して目標に一番近いものを配る（`WAYS_*`）
  - 6割未満の盤面でも、補充のたびに約10%で「**1つずつなら4か所以上に置けるのに、3つとも置ける置き方は1〜2通り**」の組み合わせ。
    大きい形で押し込むのではなく、形を1つずつ入れ替えて置き方を減らしていく探索で作る（`TIGHT_*`）
  - **詰む組み合わせを配るのは**、8割以上埋まっていて、詰まない組み合わせが置き方1通りだけ、かつその置き方だと置き終えた盤面が
    前に配った時の盤面と同じになる（ループする）ときだけ
  - 探索は占有だけを持つ軽い盤面（`src/core/sim.js`、本体と同じ結果になることをテストで確認）で行う
- **盤面が空のとき**（ゲーム開始・全消しの直後）は **約60%** で、「**6個以上（主に9個）をこの順番・この場所に置いた時だけ、
  最後の1個でちょうど全消し**」になる手順を配る（3個ずつ。`EMPTY_ALL_CLEAR_RATE`）
  - 手順は `node scripts/build-allclear.mjs` で大量に探して、本体で置き直して確かめたものを `src/core/allclear-library.js` に
    同梱している（600本: 6個 120 / 9個 360 / 12個 120。縦横を入れ替えた手順も含む）。ゲーム中は探さないので重くならない
  - 最後の1個は3連鎖以上で全部消える。1回目のトレイだけでも置き方は500通り以上あり、その中の1通りでないと手順どおりにならない
  - 手順どおりの盤面になっていなければ（違う置き方をしたら）、そこで計画はおしまい（探し直して助けない）
- **全消しのチャンス**（盤面にブロックが残っているとき。埋まり具合は問わない）: 補充のたびに **約20%** で、今の盤面から
  「**6・9・12個のどれかを、この順番・この場所に置くと、最後の1個でちょうど全消し**」になる手順を計算して3個ずつ配る
  （`ALL_CLEAR_RATE` / `ALL_CLEAR_PIECES`）
  - 手順は途中で空にならない。1マスの形は1個まで、同じ種類は2個まで。既存の形だけを使う
  - 探索は約 `ALL_CLEAR_BUDGET_MS` ms で打ち切り、見つからなければ普通の手駒にして次の補充でもう一度探す
  - 手順どおりの盤面になっていなければ（違う置き方をしたら）、そこで計画はおしまい（盤面が空のときの手順と同じ）
- ラインは縦と横の2種類で、**まったく同じルール**（盤面は対角線について対称）：
  - 縦N = 右から N 本目の列（N マス）。右端が縦1。斜辺側の端は**下端**
  - 横N = 下から N 本目の行（N マス）。下端が横1。斜辺側の端は**右端**
- ラインN が満杯（ちょうど N 個）になると発動：ラインごと通路へ抜け、ベルトコンベアのように流れる
  （縦は盤面の下を右へ、横は盤面の右を下へ）。斜辺側の端のブロックが右下の共通ゴールへ入り、
  残りは同じ種類の N-1 … 1 番ラインへ斜辺側の端から入る。入ったブロックは**ブロックか壁に当たる手前まで奥へ進む**
  （他のブロックは動かない）。ただし入る先のラインの**手前の端が埋まっている**ときは、一番近い空欄までのブロックを
  奥へ1マスずつ詰めて、空いた手前の端に入る。満杯のときだけ、そのブロックはゴールへ流れる。
- 処理順（1本発動するごとに盤面を再判定）：
  - 同じ向きの中では**番号が小さいライン**から
  - 縦と横の両方に満杯のラインがあるときは、それぞれの最小ラインから始めた場合を最後までシミュレーションして、次の順に選ぶ
    1. **詰まない向き**: まだトレイに残っている手駒が、全部置ける ＞ どれか1つは置ける ＞ 1つも置けない（詰み）
    2. **連鎖が大きくなる向き**
    3. それでも同じなら縦
    （トレイの最後の1個を置いたときは、残りの手駒が無いので 2 から。手駒の組み合わせを決めるときの読み・学習モードのおすすめ・
    仮置きの表示も、同じ決め方でシミュレーションする。`sim.js` の `nextActivation`）
- どのピースも置けなくなったらゲームオーバー。
  判定自体は置いた瞬間（連鎖が確定した時点）で決まるが、「置ける場所がない！」画面は連鎖の再生が終わるまで出さない
  （連鎖の途中でも、まだ置いていないトレイのピースは掴んで動かせる。実際には置ける場所が無いので、離すとトレイへ戻る）。
- ルールは置いた瞬間に最後まで確定し、アニメーションは後から再生される。再生中でも次のピースを置ける。
  連鎖が進んでも再生は速くならない（どの連鎖も同じ速さ）。再生中に次のピースを持ち上げると、置くまでに追いつくよう
  残りの再生を速める（下記）。それでも再生中に置いたら、残りの再生は演出なしで一気に最後まで進める
  （表示が盤面に遅れたままだと、新しいピースが古いブロックに重なって見えるため。全消しの演出だけは出す）。
  追いつくまでは仮置きを出さず、落としたときもほぼ真下にしか吸い付かない（見えていない場所に置かれないように）。
  持っているだけなら速めない。盤面へ近づけているときだけ、今の近づく速さで盤面に届くまでの時間を見積もり、
  それまでに再生が終わらない分だけ速める（間に合うなら速めない。盤面の上ではもうすぐ置くものとして、盤面に着いてから 0.2 秒で終わる速さ。最大 2 倍）。
  残りの再生時間は、流れこむブロックが一番遠くまで進むマス数まで数えて見積もる（少なく見積もると途中で速まらなくなるので）。
  追いついたら仮置きを出す。
- 操作の細かいところ:
  - 持ち上げた指だけを追う（ほかの指で触っても、持っているピースは動かない・落ちない）
  - 指が離れたのが届かなかったとき（通知・アプリの切り替えなど）は、持っていたピースをトレイに戻す
  - 一時停止すると連鎖の再生も止まる（持っていたピースは戻す）
  - 連鎖の再生中にモードを切り替えても（= 新しいゲーム）、前のゲームの続き（ブロック・点数・ゲームオーバー）は出ない
  - ベストスコアはゲームオーバー・もう一度・モードの切り替え・アプリを閉じたときに残す（モードごとに別）

## 演出
- 配置音は **ガラスのコップをテーブルに置く音**（`src/ui/synth.js` の `glassBuffer`）: 縁の「カチッ」+ ガラスの共鳴
  （薄いガラスの曲げ振動の、整数でない部分音 1 : 2.83 : 5.42 : 8.77。基本は 2 つに割れてうなる）+ 底がテーブルに当たる低い「コツ」
  + ごく小さな再接触。コップの高さ違いの 4 種を順番に使い、ピースのマス数が多いほど低く重く鳴らす。
  着地は 240ms（ぴったりなら 290ms）。列から流れる間はブロックと盤面の大きさを固定し、同色の小さなかけらを添える。
- **シャラン**（`shalanBuffer`。クリスマスのベルのような音）: 満杯になったラインの枠が光る瞬間に鳴る。小さな鈴がまとめて揺れる
  「シャ」（ランダムな打撃が 2.5〜6.5kHz の共振を次々に鳴らす）→ ベルの音階が駆け上がり（バーツリーのように）→
  最後の音が長く響く「ラン」（ベルの部分音 1 : 2.756 : 5.40 : 8.93、約 1.2 秒）。高さはゴールの音と同じ音階の 2 オクターブ上で、
  連鎖が進むほど高くなる（8 連鎖までは別の高さ）。全消しは「シャラン、シャラン」の 2 回、新記録のファンファーレは 1 回
- ガラス・シャランの波形は、DOM にも WebAudio にも依存しない純粋な計算（モーダル合成: 消えていく正弦波の足し合わせ + 打撃の短いノイズ。
  乱数は固定シードで毎回同じ音）で、1 回だけ作って `AudioBuffer` にして使い回す（起動後の空き時間に先に作る。`Sfx.warm`）。
  1 回の発音が 1 ボイスなので、同時発音の枠（40）を使い切らない。高い響きは、ほかの音を丸めている 3.8kHz のローパスを通さない
  「明るい出口」（9.5kHz のローパス。音量・ミュートは同じ）から出す
- 連鎖音は2オクターブのペンタトニック。高い音を同じ周波数へ切りそろえず、オクターブを下げて和音の違いを保つ。
  長い連鎖は旋律を繰り返しながら和音を足す。褒め言葉の和音は段階が上がったときだけ鳴らす。
- ホバー・着地音は短い間隔でまとめ、同時発音は40音まで。ミュートは予約した音も停止し、端末に設定を保存する。
  一時停止では盤面内の演出と遅延処理も止まり、リセットすると前のゲームの音・かけら・遅延処理を破棄する。
  詳しい分析・演出の数値は [docs/feedback-design.md](docs/feedback-design.md)。
- デザインの方針: 盤面・ブロック・文字・背景が1つの絵として馴染むことを優先する
  - 盤面の中の演出は**動き**（弾む・縮む・揺れる・寄る）と、**ブロックと同じ塗りのもの**（宝石のかけら・マスに満ちる色）、
    それに**ラインの光**（満杯の枠・通り過ぎた跡の白い縁・先のとがった星。下記）。ぼんやり丸く光る粒・輪・フレア・火の粉・花火・紙吹雪や
    画面のフラッシュは使わない（宝石の陰影と合わず、浮いて見えるので）。光はくっきりした形で、ほんの短い間だけ
  - 宝石・色の塊は半透明にしない（背景と混ざって濁るので）。出し入れは大きさ（scale）で行い、濃さは変えない。薄れて消えるのは光（枠・星）だけ
  - 文字（スコア・連鎖・COMBO・得点）はすべてベタ塗り + 真下への薄い影（`--ts`）。ふち取り・光のにじみ・グラデーションの文字は使わない
  - 背景の色は、白い固定の文字・ボタンが読めるよう、今の青と同じ明るさ（OKLCH の L）のまま色相だけを回す（下記）
- ブロックの動きはゆっくりめ（1マス 60ms。連鎖が進んでも速くしない）:
  - 発動の直前にラインのブロックがぎゅっと縮み、ラインの番号が弾む「溜め」（150ms）→ 解放
  - 列からの移動中は盤面を固定する。溜めの縮みは宝石の面だけに掛け、座標を持つ親要素は拡縮しない
  - 配られるブロックが入っていく列の番号の後ろにブロックの色の丸が出て、止まった瞬間に小さな音（ブロックは弾ませない）
  - 発動したラインのマスには、列車が通り過ぎた順にブロックの色が満ちて引いていく（マスのくぼみの底に色が溜まる見え方）
  - **ラインが満杯になった瞬間**（溜めの始まり。連鎖の 2 番目以降は発動の始まり。`Renderer.lineGlow`）: そのラインの枠が白く光り
    （ふちは白、外側と内側にブロックの明るい色のにじみ）、光の帯が流れる向きに走り抜け、星（先のとがった四方の星 + 小さな斜めの星。
    `src/ui/sparkles.js`）が順にきらきらとまたたく。シャランの音もここ。溜めと発動で同じラインに二重に出さない
  - **ブロックが通り過ぎた跡**（`Renderer.trail`）: 列車の後ろが抜けたマスの縁が白く光って 0.3 秒で引き、星が 1 つまたたく。
    ラインの外（斜辺と通路の間・通路の入り口）も、ゴールの手前まで 9 マス続く（光る要素は動いているブロックより下 = ブロックの後ろ）。
    ゴールに入る瞬間は、ゴールの回りに星がはじける（`goalSparkle`）
  - ゴールに入るブロックは縮んで消え、ゴールがぽんと弾んで中が入ったブロックの色で満ちる。ゴールから宝石のかけら
    （ブロックと同じ4つのふちの面とテーブル面・同じ光の向き。回さない）が上へはじけて落ちる。
    得点が浮かぶ（白 → 3連鎖〜 金 → 5連鎖〜 桃）。スコアは数字がくるくる増える
- 2連鎖以上で `n CHAIN` と `Good! → Great! → Excellent! → Amazing! → Unbelievable!`（段階ごとに文字の色と和音が変わる。
  Unbelievable は文字の色がブロックの色を順に移る）。ふち取りが無くてもブロックに埋もれないよう、盤面の上の空いた所に出す。
  大きい文字は1文字ずつ上から落ちてきて弾み、褒め言葉はそのあと下からせり上がる
- 連続発動ターンは `COMBO n`（白と金の文字）
- **背景の色**（`src/ui/ambient.js`）: ゲームの始まりは今の青。白い固定のスコア・ボタン・文字が読めるよう、明るさ（OKLCH の L）は
  今の青にそろえたまま色相だけを回す（白との対比は縁で 6〜7、中央の明るい所でも 5 前後）。同じ色相に「淡い（soft）」「濃い（deep）」の 2 段を足す
  - 発動しない手が 5 回続くたびに、ふだんの色が 27° ずつゆっくり進む（3 秒かけて）
  - コンボは 1 つ増えるたびに色相が 34° 進み、濃さも 淡い → 濃い → 標準 と変わる（1.4 秒かけてグラデーション）。5・10・15… は一気に（約 0.16 秒）
  - Amazing 以上の連鎖は一気に明るい別の色へ（1.5 秒見せて戻る）、全消しは色相をぐるりと 1 周して少し先の色へ（1.9 秒）、
    新記録は一気に別の明るい色へ。お祝いの色を見せている間は、手が置かれても上書きしない
  - 黄〜黄緑（80〜138°）は同じ明るさだとオリーブ色に濁るので、落ち着く先にはしない（途中を通り過ぎるだけ）。
    リスタートで今の青に戻る。チュートリアル中は変えない。動きを減らす設定では、小さな重ねを 1 回、0.7 秒以上かけて（急な点滅にしない）
  - 動かすのは opacity だけ: 色ごとの全面グラデーションの層（最大 4 枚）の新しい色を上に重ね、覆い終わった下の層は外す。
    遠い色へのグラデーションは 40° 以内の小さな重ねを続ける（遠い色を一度に混ぜると灰色に濁るので）。
    ブラウザの上のバー（`theme-color`）と、コンボ・ピンチ・色の変化の同系色（CSS 変数 `--amb-glow`）も背景の色相に合わせる
- **ALL CLEAR**: 画面を覆う演出は使わない（盤面の中だけ。`Renderer.allClearBlast`）。`n CHAIN` と同じ場所に `ALL CLEAR!` の文字（`t5`。虹色）と
  `BONUS +n`。空になった全マスに、盤面の中心から輪になって順に7色の宝石（盤面のブロックと同じ `.block` の塗り）がぽんと満ち、
  同じ順に砕けて小さくなりながら、ブロックと同じ塗りのかけらを散らす。砕けるたびに盤面がぐっと寄る。
  宝石は半透明にせず大きさだけで出し入れする。遅い端末・動きを減らす設定では、マスに色が満ちるだけ
- 画面全体の演出（`src/ui/scenes.js`。奥の色の変化と、新記録の風船だけ。それ以外は画面を覆わない）:
  - **Amazing 以上の連鎖・COMBO 5・10・15…**: 背景の色相に合わせた薄い同系色（`--amb-glow`）を重ねる
    （連鎖は 12・16…でもう一度。続けて重ならないよう 1.1 秒あける）。背景そのものの色も一気に変わる（上記）
  - **NEW BEST**: 薄い同系色を重ね、ベストスコアの枠がぽんと弾んで7色のかけらがはじけ、画面の左下・右下から
    かけらが2回噴き上がって落ちてくる。`n CHAIN` と同じ場所に `NEW BEST!` の文字（`t5`）・ファンファーレ
  - 画面全体で飛び散るものも、盤面のかけらと同じ絵（`shards.js` の `gemSprite`: ブロックと同じ4つのふちの面とテーブル面・
    左上からの光・右下へ落ちる小さな影。回さない）。薄くせず、小さくなって消える
  - 重くしないために: 色の変化は1回だけ描いた 400px の絵を拡大し、opacity と transform だけで動かす。
    演出を描いている間のフレーム時間を測り、遅い端末では半透明の層や粒の数を減らす（`Scenes.quality`）
- 仮置き（指に付けたまま盤面に重ねる）: 消える列のブロックを持っているピースの色に塗り替えて白いふちで脈打たせ、
  その列の番号にも色の丸が出て、GOAL が弾む。消える場所に入った瞬間に上昇音と軽い振動、ピースの上に `CLEAR` / `⚡n CHAIN`
- 穴・凹みにはまる場所に持っていくと、仮置きがきゅっと吸い込まれるように収まる。ぴったり・長方形の場所ではさらに濃くなって
  カチッと鳴る。置くと `PERFECT FIT!`（穴）/ `NICE FIT!`（長方形）とボーナス点、カチッ + 上がる2音。
  はまること自体が気持ちよさなので、枠などの印は出さず、長方形ができてもブロックは消えない
- 盤面が混んだり、置けない手駒があるピンチのときは画面の縁が暖色でゆっくり脈打つ（発動で空くと消える）
- ゲーム中にベストスコアを超えた瞬間にベストスコアの枠が金色になって弾む
- 長い連鎖でもカクつかないように:
  - 同時にゴールへ入るブロックの演出と音は1回にまとめる
  - 宝石のかけらは色ごとに1回だけ描いた小さな絵（`src/ui/shards.js`）を貼って transform だけで動かす
    （CSS のグラデーションで塗ると出すたびに描き直しになり、盤面を覆う canvas は空でも重ね合わせが重くなる）。同時に 14 個まで
  - マスに満ちる色の要素はマスごとに1つを最初に作って使い回す
  - ブロックが動いている間のフレーム時間を測り、遅い端末では かけら・波打ち・1文字ずつの文字・マスに満ちる色 を自動で減らす（`Renderer.q`）
  - アニメーションのやり直しに `offsetWidth` を読む強制レイアウトは使わない（Web Animations か要素の差し替え）
  - 背景の変化（コンボ・ピンチ）は opacity と scale だけを動かす（filter や box-shadow を毎フレーム動かさない）
  - ラインの光: 星は色ごとに 1 回だけ描いた絵（`sparkles.js`）を貼って scale・rotate・translate だけで動かす（同時に 36 個まで）。
    枠と通り過ぎた跡は opacity と scale だけ。遅い端末では、星（品質 0.6 未満）→ 跡の光（0.5 未満）の順に減らし、枠だけにする。
    動きを減らす設定では、枠がふわっと光って消えるだけ（帯・星・跡は出さない。音は鳴る）。早送りでは出さない。
    速い再生（再生待ちが溜まったとき）では枠の光も短くして、重ならないようにする
- 画面を止めないために（演出・ルール・ロジックの結果は変えずに）:
  - **手駒の決め方と学習モードのおすすめの総当たりは Web Worker で動かす**（`src/core/dealer-worker.js`。窓口は
    `src/ui/tray-dealer.js`、中身は `src/core/dealer.js` が `Game.spawnTray` / `advisor.bestMove` をそのまま呼ぶ）。
    手駒の探索は時間で打ち切る作りで 1 回に 100ms 近くかかることがあり、メインスレッドで動かすと置いた瞬間に画面が止まるため。
    決め方のコード・時間の上限は同じで、補充の手駒は決まったらトレイに出る（それまでトレイは空。詰みの判定は届いてから）。
    Worker が使えない・読み込めない環境では、同じ処理をメインスレッドで行う。同じ乱数・同じ時間の進み方なら、
    同期で決めた場合とまったく同じ進行になることをテストで確認している
  - 虹色の文字（`t5`）の色の移り変わりは、文字が見えている間だけ（無限にすると、消えた後も毎フレーム色の計算と描き直しが続く）
  - ドラッグ中は盤面の位置を読んでからピースを動かす（書いてから読むと、動かすたびにレイアウトの計算し直しになる）。
    仮置きの情報（消えるライン・連鎖数）と、縦横どちらを先に発動するかの読みは、探索用の軽い盤面（`sim.js`）で計算する
    （結果は盤面本体と同じ。テストで確認）
  - 同じ値のスタイル・文字は書き直さない。トレイの寸法は大きさが変わったときだけ測る。置いたブロックの弾みのやり直しに強制レイアウトを使わない
  - かけらの絵は色ごとの CSS クラスで 1 回だけ読み込ませる。かけら・虹色の絵は起動後の空き時間に作っておく（最初に出る瞬間に止まらないように）

## 途中から再開
- ゲームの途中の状態（盤面・トレイ・スコア・全消しの手順・手駒の決め方の状態）を端末に残し、次に開くとそのままの盤面から続く
  （説明などは出さない。置くたび・手駒が届いたとき・アプリを閉じる/隠れるときに残す。ゲームオーバー・もう一度で消える。モードごとに別）
- 1手戻す機能は無い

## チュートリアル（はじめて遊ぶ人向け）
- はじめて開いたとき（ベストスコアも途中の保存も無い）に、遊びながらルールを覚える5手が始まる。一時停止の「遊び方」からもう一度見られる
  1. ピースをつかんで置く
  2. ラインは番号の数だけ入ると満杯 → 発動。1個は GOAL、残りは小さい番号のラインへ1個ずつ流れこむ（縦3。2連鎖）
  3. ブロックの動き方: 横のラインも同じルール。流れこんだブロックは奥へ進み、ブロックか壁の手前で止まる（横5）
  4. 押しこみ: 入る先のラインの入口（斜辺側の端）がふさがっていると、中のブロックを奥へ1マス押して入る（縦4。4連鎖）
  5. 連鎖のコツ: 横1〜4 を「あと1個」にしておき（番号を光らせる）、横5 を満杯にすると次々に満杯になる（10連鎖）
  6. 3つ置くと次の3つが来る・置けなくなったらおしまい・コツのまとめ →「はじめる」で本番のゲーム
- **2〜4 はブロックの動きを本物の盤面で1つずつ見せる**（`explain`。再生をゆっくりにし、途中で止めて説明する）:
  - 満杯になったラインのマスを金色の枠で囲み、番号を光らせる（少し見せたら自動で進む）
  - ラインのブロックが通路へ流れ、先頭の1個が GOAL に入ったところで止める（GOAL が弾む）
  - 残りのブロックが止まるマスに白い枠（中にそのブロックの色）を出し、入る先のラインの番号をブロックの色で光らせる。
    押しこまれるブロックの行き先にも枠を出す。そこから入っていくのを見せる
  - 止まっている間は説明の下に「次へ」が出て、画面のどこをタップしても進む（出した直後のタップは数えない）。
    再生が終わったら まとめ を出し、タップで次のステップへ
  - 止める場所は `Renderer.playStep` の `pause`（普段の再生では使わない）
- 置く場所は金色の枠で示し、指の絵がトレイのピースを運んで見せる。決めた場所にしか置けない（近くで離せば吸い付く）
- 盤面と手駒は `src/ui/tutorial-steps.js` で決めている（前の手の結果に足りないブロックを足してつなぐ。連鎖数・押しこみが起きることはテストで確認）。
  チュートリアル中は補充・詰みの判定・ベストスコア・途中の保存は無し（`Game.scripted`）。説明はスコアの場所に出す
- 「スキップ」か「はじめる」で終わる。遊んでいる途中に「遊び方」を見たときは、そのゲームの続きに戻る
- LINE・Instagram・Facebook などのアプリ内ブラウザで開かれたら、Safari / Chrome で開き直す
  （LINE は `openExternalBrowser=1`、iOS は `x-safari-https://`、Android は Chrome の intent）

## 学習モード
- 左上の電球ボタンで通常モードと切り替える（切り替えると新しいゲームになる。選んだモードは端末に記憶）
- 次に置くとよいピースと場所を示す（盤面に白い枠＋中にピースの色の小さな面が脈打つ、トレイのそのピースが弾む）。AI ではなく今の盤面での総当たり
  （`src/core/advisor.js`）:
  - 置いたあと残りの手駒を全部置き切れる手（詰まない手）を最優先
  - そのうえで、その手で入る点数 + 置いたあとの盤面の良さ（ブロックが少ない・満杯まであと1個のラインが多い・大きい形を置ける場所が残る）
    + もう1手先で入る点数と盤面の良さ（半分の重み）が一番大きい手
  - 全消しの手順中は、手順どおりの次の手を金色の枠で教える（そのとおりに置くと全消し）
- スコアの計算は同じだが、ベストスコアは通常モードとは別に記録する

## スコア
- 置いたマス ×1、ゴールに入った1個 ×90（連鎖・コンボの倍率を掛ける前の基本点。コンボ倍率が ×1.3 ずつ伸びるので、100 の 0.9 倍にしてある）
- **ぴったりボーナス**: 穴にぴったり置くと、置いたマス1つにつき +25（`SCORE_PER_PERFECT_FIT_CELL`）
- **長方形ボーナス**: 置いて長方形がそろうと、長方形のマス1つにつき +10（`SCORE_PER_RECT_CELL`。ぴったりと両方なら足す）
- 連鎖倍率: 2連鎖 ×2 → 3連鎖 ×3 → 4連鎖 ×5 → 5連鎖 ×8 → 6連鎖 ×12 → … → 12連鎖 ×50 → そのあとも1連鎖ごとに +10（**上限なし**。13連鎖 ×60、20連鎖 ×130）
- 連続発動ターン(COMBO)倍率: COMBO 1 つごとに **×1.3 を掛けていく**（COMBO 2 = ×1.3、3 = ×1.69、5 ≒ ×2.9、8 ≒ ×6.3、12 ≒ ×18。上限なし）。連鎖倍率と掛け合わせる
  - COMBO = 置くたびに何かが発動した手の連続数。発動しない手を置くと途切れる

## 記録
- モードごとに、ベストスコア・**最大連鎖**・**最大コンボ**を端末に残す（ベストスコアと同じ時に残す。チュートリアルは残さない）
- 端末に残す記録の名前はすべて `blockmancala-` で始まる（ゲーム名にそろえた）。前の名前（`stair-mancala-`）で残っている記録は、
  起動したときに新しい名前へ移してから消す（新しい名前がもうあればそちらを残す。`brand.js` の `migrateStorage`。テストで確認）
- ゲームオーバー画面に、このゲームの最大連鎖・最大コンボと、これまでの記録（超えたら `NEW RECORD!`）
- 一時停止画面にも記録を出す
- **ランキング**（スコアだけ）: 右上のトロフィーのボタン（ゲームオーバー画面の「ランキングを見る」からも）。**世界** と **この端末** を選べる
- **世界ランキング**（`functions/api/ranking.js`。Cloudflare Pages Functions + D1）: 1人1行の自己ベストで、**最下位まで**スクロールで見られる（50人ずつ、下の端が近づくと続きを読み足す）。自分の順位と参加人数も出す
  - 通常モードのスコアだけを送る（学習モードは入らない）。送れなかったスコアは端末に残し、次に送る。ランキングができる前の通常モードのベストスコアも、はじめに送る
  - 端末ごとに id（32桁の16進。他の人には返さない）と名前（12文字まで）を持つ。**名前は自動では付けず、プレイを始める前に必ず決めてもらう**（はじめて開いたとき、または名前がまだ無いとき。決めるまで盤面には触れない・空では決められない・チュートリアルもそのあと）。決めるとすぐ世界ランキングに参加する。あとはランキング画面の「変更」で変えられる
  - ゲームは端末の中で動くので、送られた値が本物かまでは確かめられない（ありえない値だけはねる）
  - **準備**（Cloudflare のダッシュボードで1回だけ）: D1 のデータベースを作り（名前は自由）、Pages のプロジェクトの Settings → Bindings で **変数名 `DB`** としてつなぎ、もう一度デプロイする。表は初めて使うときに API が作る
  - `blockmancala.pages.dev` 以外（github.io など）で開いたときは、`blockmancala.pages.dev` の API を使う
  - **不適切な名前を隠す**（作成者だけ）: `admin.html`（`blockmancala.pages.dev/admin.html`。ゲームからはリンクしない）で、名前を「隠す」にできる。
    隠した名前は、ほかの人には `＊＊＊`（順位・スコアはそのまま）、本人の画面には本人の名前のまま出る（隠されたことに気づかない）。
    名前の**書き換えはできない**。隠しているのは「そのときの名前」だけで、本人が名前を変えたら新しい名前はふつうに出る（まだ不適切なら、もう一度隠す）
  - **準備**（合言葉）: Pages の Settings → Variables and Secrets に **Secret として `ADMIN_KEY`（16文字以上）** を入れて、もう一度デプロイする。
    入れていない・短いときは、管理 API（`functions/api/admin.js`）は使えない（503）。管理画面は `Authorization: Bearer <ADMIN_KEY>` で呼ぶ（合言葉はこのタブを閉じるまでしか覚えない）
- **この端末のランキング**: 上位10ゲーム（端末ごと・モードごとに別。`blockmancala-ranking` / `-learn`。`src/core/ranking.js`）
  - 1ゲームを1件として、ゲームオーバーとリセットのときに入れる（チュートリアルと 0 点は入れない）。いちばん最近入ったゲームは金色の枠
  - ランキングができる前のベストスコアは「以前の記録」として入れる
- **全消しボーナス** +5,000（そのターンの COMBO 倍率も掛ける）。`ALL CLEAR!` の下に `BONUS +n` を出し、GOAL の上に得点が浮かぶ
  - さらに全消しのあと **5手のあいだ、手に入るスコアすべてが ×1.5**（置いたマス・はまり方のボーナス・発動）。画面には出さない。
    もう一度全消しすると手数が5に戻る（倍率は重ねない）。途中の保存にも残る
- すべて `src/core/constants.js`

## ホーム画面に追加
- `manifest.webmanifest`（アプリ名・アイコン・`display:standalone`）と、iOS Safari 用のメタタグ（`apple-touch-icon` など）を用意。
  ブラウザの「ホーム画面に追加」でアイコン付きのアプリとして起動できる（オフライン対応はしていない。開くたびに通信は発生する）
- アイコンは `icons/`（`icon-192.png` / `icon-512.png` / `icon-512-maskable.png` / `apple-touch-icon.png` / `favicon-16・32.png`）。
  元絵は `index.html` 冒頭の `<link rel="icon">` に書いてあるインラインSVGと同じ意匠（階段の形）を、
  サイズ別に書き出したもの。作り直すときはそのSVGを編集してから、大きさごとにラスタライズし直す

## 画面
- 上: 左上にリセット・学習モード、中央にベストスコア（王冠のピル）、右上にランキング・サウンド・一時停止の各ボタン。中央に現在のスコア（ベストスコアも3桁区切り）

  詰んだらゲームオーバー画面の「もう一度」でも再開できる。デバッグパネルは URL に `?debug` を付けたときだけ表示
