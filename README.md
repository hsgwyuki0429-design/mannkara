# STAIR MANCALA

三角形の盤面 × ブロックブラスト式配置 × マンカラ式配布のパズル。静的サイトのみ（バックエンド不要）。

## ルール
- 盤面は 8×8 を対角線で切った三角形。
- 下のトレイの3ピースを**指でつかんで盤面の空きへ置く**。回転なし・重力なし。3つ使い切ると補充。
- 手駒は**テトロミノ7種 + ブロックブラストの形**（1マス・直線2/3/5・3×3・2×3・小さいL(3マス)・大きいL(5マス)）。
  さらに三角の盤面に合わせた形: **斜め点線**（ななめ2・3。どのマスも別の縦・横に入り、何本ものラインの最後の1マスを同時に埋める）・
  **逆斜め**（ななめ2・3。斜辺と平行で、ラインの斜辺側の端をまとめて埋める）・**階段ヘビ**（W型5マス）・**十字**（5マス）。
  21種類×全向き＝46種。種類ごとの出やすさは `src/core/pieces.js` の重み（テトロミノ各1、1マスは0.5、3×3は0.6 など）。
  各枠 **約10%** の確率で、今の盤面のどこかに置けば発動が起きる形が選ばれる（`CHAIN_PIECE_RATE`）。
  さらに各枠 **約30%** で、**今の盤面の穴・凹みに気持ちよくはまる形**が選ばれる（`FIT_PIECE_RATE`）。列を消すのとは別に
  「空いている所にぴったり入れたい・凹みを埋めて四角くそろえたい」気持ちに応えるため。はまり方（`Sim.fitOf`）は3つ:
  - **ぴったり**（perfect）: 置くとまわりの空きに1つも接しない＝ブロックに囲まれた穴をちょうど埋める
  - **長方形**（rect）: 置くと、形がまるごと入るすきまの無い長方形（縦横2マス以上・6マス以上・前からのブロック2個以上）ができる
  - **凹み**（dent）: ブロックに接し、ふさがる辺（ブロック + 盤面の外）が空きに接する辺より多い
  選ばれやすさは ぴったり 8 : 長方形 6 : 凹み 1（× 形のマス数。`FIT_WEIGHTS`）
- 新しい3つの決め方（埋まり具合 = 「連鎖が終わった盤面に残せる最大 28 個」に対する割合。縦横16本すべてに空きが要るので、
  36マスのうち最低8マスは必ず空く）:
  - 埋まり具合に関係なく、**必ず詰まない置き方が1つ以上ある**組み合わせ（連鎖込みの探索で確認）
  - **置き方の数**（3つとも置き終えた盤面の種類。順番を入れ替えただけのものは1通り）を、埋まり具合に比例して桁で減らす。
    目標 = 300^(1 - 埋まり具合)（空 300 → 半分 17 → 8割 3 → 満杯 1）。候補を抽選して目標に一番近いものを配る（`WAYS_*`）
  - 6割未満の盤面でも、補充のたびに約10%で「**1つずつなら4か所以上に置けるのに、3つとも置ける置き方は1〜2通り**」の組み合わせ。
    大きい形で押し込むのではなく、形を1つずつ入れ替えて置き方を減らしていく探索で作る（`TIGHT_*`）
  - **詰む組み合わせを配るのは**、8割以上埋まっていて、詰まない組み合わせが置き方1通りだけ、かつその置き方だと置き終えた盤面が
    前に配った時の盤面と同じになる（ループする）ときだけ
  - 探索は占有だけを持つ軽い盤面（`src/core/sim.js`、本体と同じ結果になることをテストで確認）で行う
- **盤面が空のとき**（ゲーム開始・全消しの直後）は **約60%** で、「**6個以上（主に9個）をこの順番・この場所に置いた時だけ、
  最後の1個でちょうど全消し**」になる手順を配る（3個ずつ。`EMPTY_ALL_CLEAR_RATE`）
  - 手順は `node scripts/build-allclear.mjs` で大量に探して、本体で置き直して確かめたものを `src/core/allclear-library.js` に
    同梱している（600本: 6個 120 / 9個 360 / 12個 120。縦横を入れ替えた手順も含む）。ゲーム中は探さないので重くならない
  - 最後の1個は3連鎖以上で全部消える。1回目のトレイだけでも置き方は500通り以上あり、その中の1通りでないと手順どおりにならない
  - 手順どおりの盤面になっていなければ（違う置き方をしたら）、そこで計画はおしまい（探し直して助けない）
- **全消しのチャンス**（盤面にブロックが残っているとき。埋まり具合は問わない）: 補充のたびに **約20%** で、今の盤面から
  「**6・9・12個のどれかを、この順番・この場所に置くと、最後の1個でちょうど全消し**」になる手順を計算して3個ずつ配る
  （`ALL_CLEAR_RATE` / `ALL_CLEAR_PIECES`）
  - 手順は途中で空にならない。1マスの形は1個まで、同じ種類は2個まで。既存の形だけを使う
  - 探索は約 `ALL_CLEAR_BUDGET_MS` ms で打ち切り、見つからなければ普通の手駒にして次の補充でもう一度探す
  - 手順どおりの盤面になっていなければ（違う置き方をしたら）、そこで計画はおしまい（盤面が空のときの手順と同じ）
- ラインは縦と横の2種類で、**まったく同じルール**（盤面は対角線について対称）：
  - 縦N = 右から N 本目の列（N マス）。右端が縦1。斜辺側の端は**下端**
  - 横N = 下から N 本目の行（N マス）。下端が横1。斜辺側の端は**右端**
- ラインN が満杯（ちょうど N 個）になると発動：ラインごと通路へ抜け、ベルトコンベアのように流れる
  （縦は盤面の下を右へ、横は盤面の右を下へ）。斜辺側の端のブロックが右下の共通ゴールへ入り、
  残りは同じ種類の N-1 … 1 番ラインへ斜辺側の端から入る。入ったブロックは**ブロックか壁に当たる手前まで奥へ進む**
  （他のブロックは動かない）。ただし入る先のラインの**手前の端が埋まっている**ときは、一番近い空欄までのブロックを
  奥へ1マスずつ詰めて、空いた手前の端に入る。満杯のときだけ、そのブロックはゴールへ流れる。
- 処理順（1本発動するごとに盤面を再判定）：
  - 同じ向きの中では**番号が小さいライン**から
  - 縦と横の両方に満杯のラインがあるときは、それぞれの最小ラインから始めた場合の**連鎖数を比べ、
    大きくなる向き**の最小ラインから（同じなら縦）
- どのピースも置けなくなったらゲームオーバー。
- ルールは置いた瞬間に最後まで確定し、アニメーションは後から再生される。再生中でも次のピースを置ける。
  連鎖が進んでも再生は速くならない（どの連鎖も同じ速さ）。再生中に次のピースを持ち上げると、置くまでに追いつくよう
  残りの再生が `BACKLOG_SPEED` 倍速になる。それでも再生中に置いたら、残りの再生は演出なしで一気に最後まで進める
  （表示が盤面に遅れたままだと、新しいピースが古いブロックに重なって見えるため。全消しの演出だけは出す）。
  追いつくまでは仮置きを出さず、落としたときもほぼ真下にしか吸い付かない（見えていない場所に置かれないように）。
  持ち上げている時間が長いほど速め（最大 12 倍）、追いついたら仮置きを出す。
- 操作の細かいところ:
  - 持ち上げた指だけを追う（ほかの指で触っても、持っているピースは動かない・落ちない）
  - 指が離れたのが届かなかったとき（通知・アプリの切り替えなど）は、持っていたピースをトレイに戻す
  - 一時停止すると連鎖の再生も止まる（持っていたピースは戻す）
  - 連鎖の再生中にモードを切り替えても（= 新しいゲーム）、前のゲームの続き（ブロック・点数・ゲームオーバー）は出ない
  - ベストスコアはゲームオーバー・もう一度・モードの切り替え・アプリを閉じたときに残す（モードごとに別）

## 演出
- デザインの方針: 盤面・ブロック・文字・背景が1つの絵として馴染むことを優先する
  - 盤面の中の演出は**動き**（弾む・縮む・揺れる・寄る）と、**ブロックと同じ塗りのもの**（宝石のかけら・マスに満ちる色）だけ。
    ぼんやり光る丸（光の粒・光の輪・フレア・火の粉・花火・紙吹雪）や画面のフラッシュは使わない（宝石の陰影と合わず、浮いて見えるので）
  - 色は半透明にしない（背景の青と混ざって濁るので）。出し入れは大きさ（scale）で行い、濃さは変えない
  - 文字（スコア・連鎖・COMBO・得点）はすべてベタ塗り + 真下への薄い影（`--ts`）。ふち取り・光のにじみ・グラデーションの文字は使わない
  - 画面全体の色の変化は、背景の青と混ざっても濁らない水色・青緑・青紫・桃の範囲で（黄・橙を薄く重ねると灰色に濁る）
- ブロックの動きはゆっくりめ（1マス 60ms。連鎖が進んでも速くしない）:
  - 発動の直前にラインのブロックがぎゅっと縮み、ラインの番号が弾む「溜め」（150ms）→ 解放
  - 発動で盤面が揺れる（連鎖ほど強く）。4連鎖目からは画面がぐっと寄る
  - 配られるブロックが入っていく列の番号の後ろにブロックの色の丸が出て、止まった瞬間にぽよんと弾む・小さな音
  - 発動したラインのマスには、列車が通り過ぎた順にブロックの色が満ちて引いていく（マスのくぼみの底に色が溜まる見え方）
  - ゴールに入るブロックは縮んで消え、ゴールがぽんと弾んで中が入ったブロックの色で満ちる。ゴールから宝石のかけら
    （ブロックと同じ4つのふちの面とテーブル面・同じ光の向き。回さない）が上へはじけて落ちる。
    得点が浮かぶ（白 → 3連鎖〜 金 → 5連鎖〜 桃）。スコアは数字がくるくる増える
- 2連鎖以上で `n CHAIN` と `Good! → Great! → Excellent! → Amazing! → Unbelievable!`（段階ごとに文字の色と和音が変わる。
  Unbelievable は文字の色がブロックの色を順に移る）。ふち取りが無くてもブロックに埋もれないよう、盤面の上の空いた所に出す。
  大きい文字は1文字ずつ上から落ちてきて弾み、褒め言葉はそのあと下からせり上がる
- 連続発動ターンは `COMBO n`（白と金の文字）。続くほど背景が青〜青紫の範囲でほんのり明るくなって脈打つ
- **ALL CLEAR**: 画面を覆う演出は使わない（盤面の中だけ）。`n CHAIN` と同じ場所に `ALL CLEAR!` の文字（`t5`。虹色）、
  空になった盤面のマスへ中心から7色が輪になって順に満ちて広がり、盤面がぐっと寄って戻る（`Renderer.allClearBlast`）
- 画面全体の演出（`src/ui/scenes.js`。奥の色の変化と、新記録の風船だけ。それ以外は画面を覆わない）:
  - **Amazing 以上の連鎖**: 画面全体が桃紫に染まる。Unbelievable（8連鎖〜）は水色〜青紫〜桃の輪がゆっくり回る。
    12・16…連鎖でもう一度（続けて重ならないよう 1.1 秒あける）
  - **COMBO 5・10・15…**: 画面の下から桃〜青紫に染まる
  - **NEW BEST**: 水色〜青紫に明るく染まり、風船「NEW BEST」が浮かんで割れる・ファンファーレ
  - 重くしないために: 色の変化は1回だけ描いた 400px の絵を拡大し、opacity と transform だけで動かす。
    演出を描いている間のフレーム時間を測り、遅い端末では半透明の層や粒の数を減らす（`Scenes.quality`）
- 仮置き（指に付けたまま盤面に重ねる）: 消える列のブロックを持っているピースの色に塗り替えて白いふちで脈打たせ、
  その列の番号にも色の丸が出て、GOAL が弾む。消える場所に入った瞬間に上昇音と軽い振動、ピースの上に `CLEAR` / `⚡n CHAIN`
- 穴・凹みにはまる場所に持っていくと、仮置きがきゅっと吸い込まれるように収まる。ぴったり・長方形の場所ではさらに濃くなって
  カチッと鳴る。置くと `PERFECT FIT!`（穴）/ `NICE FIT!`（長方形）とボーナス点、カチッ + 上がる2音。
  はまること自体が気持ちよさなので、枠などの印は出さず、長方形ができてもブロックは消えない
- 盤面が混んだり、置けない手駒があるピンチのときは画面の縁が暖色でゆっくり脈打つ（発動で空くと消える）
- ゲーム中にベストスコアを超えた瞬間にベストスコアの枠が金色になって弾む
- 長い連鎖でもカクつかないように:
  - 同時にゴールへ入るブロックの演出と音は1回にまとめる
  - 宝石のかけらは色ごとに1回だけ描いた小さな絵（`src/ui/shards.js`）を貼って transform だけで動かす
    （CSS のグラデーションで塗ると出すたびに描き直しになり、盤面を覆う canvas は空でも重ね合わせが重くなる）。同時に 14 個まで
  - マスに満ちる色の要素はマスごとに1つを最初に作って使い回す
  - ブロックが動いている間のフレーム時間を測り、遅い端末では かけら・波打ち・1文字ずつの文字・マスに満ちる色 を自動で減らす（`Renderer.q`）
  - アニメーションのやり直しに `offsetWidth` を読む強制レイアウトは使わない（Web Animations か要素の差し替え）
  - 背景の変化（コンボ・ピンチ）は opacity と scale だけを動かす（filter や box-shadow を毎フレーム動かさない）

## 学習モード
- 左上の電球ボタンで通常モードと切り替える（切り替えると新しいゲームになる。選んだモードは端末に記憶）
- 次に置くとよいピースと場所を示す（盤面に白い枠＋中にピースの色の小さな面が脈打つ、トレイのそのピースが弾む）。AI ではなく今の盤面での総当たり
  （`src/core/advisor.js`）:
  - 置いたあと残りの手駒を全部置き切れる手（詰まない手）を最優先
  - そのうえで、その手で入る点数 + 置いたあとの盤面の良さ（ブロックが少ない・満杯まであと1個のラインが多い・大きい形を置ける場所が残る）
    + もう1手先で入る点数と盤面の良さ（半分の重み）が一番大きい手
  - 全消しの手順中は、手順どおりの次の手を金色の枠で教える（そのとおりに置くと全消し）
- スコアの計算は同じだが、ベストスコアは通常モードとは別に記録する

## スコア
- 置いたマス ×1、ゴールに入った1個 ×100
- **ぴったりボーナス**: 穴にぴったり置くと、置いたマス1つにつき +25（`SCORE_PER_PERFECT_FIT_CELL`）
- **長方形ボーナス**: 置いて長方形がそろうと、長方形のマス1つにつき +10（`SCORE_PER_RECT_CELL`。ぴったりと両方なら足す）
- 連鎖倍率: 2連鎖 ×2 → 3連鎖 ×3 → 4連鎖 ×5 → 5連鎖 ×8 → 6連鎖 ×12 → … → 12連鎖〜 ×50
- 連続発動ターン(COMBO)倍率: COMBO 1 つごとに +0.5（COMBO 2 = ×1.5 … COMBO 11〜 = 最大 ×6）。連鎖倍率と掛け合わせる
- **全消しボーナス** +5,000（そのターンの COMBO 倍率も掛ける）。`ALL CLEAR!` の下に `BONUS +n` を出し、GOAL の上に得点が浮かぶ
- すべて `src/core/constants.js`

## 画面
- 上: 学習モード・ベストスコア（王冠のピル）・サウンド・一時停止の各ボタン。中央に現在のスコア（3桁区切り）
- 盤面は直角が下に来るよう回転した三角形。上に GOAL、左右の通路にライン番号 1〜8
- 下: 3つのトレイ（枠線も枠の四角も描かない、手駒はできるだけ盤面のマスと同じ大きさで表示。今の盤面に置けない形も、ほかと同じ見た目で表示する）。
  リスタートボタンは無く、詰んだらゲームオーバー画面の「もう一度」でだけ再開する。デバッグパネルは URL に `?debug` を付けたときだけ表示
- フォントは `src/ui/fonts/` に同梱（Nunito / M PLUS Rounded 1c、どちらも SIL OFL）。
  和文は画面で使う文字だけのサブセットなので、**新しい和文を画面に出すときはサブセットを作り直す**

## 開発
- ルールのテスト: `node test/rules.test.mjs`（DOM 不要）
- ローカル: `python3 -m http.server` で `index.html` を開く
- **デプロイ前に `node scripts/stamp.mjs`**：CSS/JS の参照に `?v=` を付け直し、スマホが古いファイルと新しいファイルを混ぜて読むのを防ぐ

```
src/core/   constants.js board.js pieces.js mancala.js score.js game.js   … ルール（DOM非依存）
            advisor.js                                                   … 学習モードのおすすめの手
            allclear-library.js                                          … 空の盤面からの全消しの手順集（自動生成）
            sim.js planner.js                                            … 手駒を決めるための探索（軽い盤面・全消しの計画）
src/ui/     renderer.js scenes.js shards.js palette.js main.js sfx.js styles.css … 描画・入力・音
test/       rules.test.mjs
scripts/    stamp.mjs build-allclear.mjs
```
