# blockmancala

三角形の盤面 × ブロックブラスト式配置 × マンカラ式配布のパズル。静的サイトのみ（バックエンド不要）。

## ルール
- 盤面は 8×8 を対角線で切った三角形。
- 下のトレイの3ピースを**指でつかんで盤面の空きへ置く**。回転なし・重力なし。3つ使い切ると補充（対戦では使った枠にすぐ補充）。
- 手駒は**テトロミノ7種 + ブロックブラストの形**（1マス・直線2/3/5・3×3・2×3・小さいL(3マス)・大きいL(5マス)）。
  さらに三角の盤面に合わせた形: **斜め点線**（ななめ2・3。どのマスも別の縦・横に入り、何本ものラインの最後の1マスを同時に埋める）・
  **逆斜め**（ななめ2・3。斜辺と平行で、ラインの斜辺側の端をまとめて埋める）・**階段ヘビ**（W型5マス）・**十字**（5マス）。
  21種類×全向き＝46種。種類ごとの出やすさは `src/core/pieces.js` の重み（テトロミノ各1、1マスは0.5、3×3は0.6 など）。
  ふつうの抽選では、各枠 **50%** で、今の盤面のどこかに置けば発動が起きる形（`CHAIN_PIECE_RATE`）、残りの **50%** で、
  **今の盤面の穴・凹みに気持ちよくはまる形**が選ばれる。どちらかの形が盤面に無いときはもう一方、両方無いときだけ重みどおりのランダム。列を消すのとは別に
  「空いている所にぴったり入れたい・凹みを埋めて四角くそろえたい」気持ちに応えるため。はまり方（`Sim.fitOf`）は3つ:
  - **ぴったり**（perfect）: 置くとまわりの空きに1つも接しない＝ブロックに囲まれた穴をちょうど埋める
  - **長方形**（rect）: 置くと、形がまるごと入るすきまの無い長方形（縦横2マス以上・6マス以上・前からのブロック2個以上）ができる
  - **凹み**（dent）: ブロックに接し、ふさがる辺（ブロック + 盤面の外）が空きに接する辺より多い
  選ばれやすさは ぴったり 8 : 長方形 6 : 凹み 1（× 形のマス数。`FIT_WEIGHTS`）
- 新しい3つの決め方（埋まり具合 = 「連鎖が終わった盤面に残せる最大 28 個」に対する割合。縦横16本すべてに空きが要るので、
  36マスのうち最低8マスは必ず空く）:
  - 埋まり具合に関係なく、**必ず詰まない置き方が1つ以上ある**組み合わせ（連鎖込みの探索で確認）
  - **置き方の数**（3つとも置き終えた盤面の種類。順番を入れ替えただけのものは1通り）を、埋まり具合に比例して桁で減らす。
    目標 = 300^(1 - 埋まり具合)（空 300 → 半分 17 → 8割 3 → 満杯 1）。候補を抽選して目標に一番近いものを配る（`WAYS_*`）
  - 6割未満の盤面でも、補充のたびに **3%**（遊んでいる人の出来で変わる。下の「ひっかけの確率」）で「**1つずつなら4か所以上に置けるのに、3つとも置ける置き方は1〜2通り**」の組み合わせ。
    大きい形で押し込むのではなく、形を1つずつ入れ替えて置き方を減らしていく探索で作る（`TIGHT_*`）
  - **ひっかけの確率は出来に合わせる**（`src/core/difficulty.js`。急に難しくなったと気づかれないよう、段差なしでなめらかに）:
    最初の 3 ゲーム **0%** / 最近 5 ゲームの平均がベストの半分未満 **1%** / ふつう **3%** /
    今のゲームがベストの 80%→100% で **3%→8%** / ベストを超えたら超えた分だけ上げて 1.3 倍で上限 **12%**。
    ひっかけを配った直後の 2 回の補充は 0%（続けて当たらないように）。チュートリアルは 3%。
    最近のスコアは端末に保存（`blockmancala-recent`、モードごと）。超えたかどうかは、そのゲームを始めたときのベストと比べる
  - **全消しのチャンスの確率も出来に合わせる**（`allClearRateFor`。最大 **40%**）: 最初の 3 ゲーム・最近 5 ゲームの平均がベストの半分未満 **40%**（全消しで一気に点が入り、立て直せる）/
    ふつう **25%** / 今のゲームがベストの 80%→100% で **25%→15%** / ベストを超えたら 1.3 倍で下限 **10%**（ベスト更新は自分の力で）。チュートリアルは 25%
  - **詰む組み合わせを配るのは**、8割以上埋まっていて、詰まない組み合わせが置き方1通りだけ、かつその置き方だと置き終えた盤面が
    前に配った時の盤面と同じになる（ループする）ときだけ
  - 探索は占有だけを持つ軽い盤面（`src/core/sim.js`、本体と同じ結果になることをテストで確認）で行う
- **全消しのチャンス**（盤面が空でもブロックが残っていても同じ。埋まり具合は問わない）: 補充のたびに **25%**（遊んでいる人の出来で変わる。下の「全消しのチャンスの確率」）で、今の盤面から
  「**6・9・12個のどれかを、この順番・この場所に置くと、最後の1個でちょうど全消し**」になる手順を計算して3個ずつ配る
  （`ALL_CLEAR_RATE` / `ALL_CLEAR_PIECES`）
  - 手順は途中で空にならない。1マスの形は1個まで、同じ種類は2個まで。既存の形だけを使う
  - 探索は約 `ALL_CLEAR_BUDGET_MS` ms で打ち切り、見つからなければ普通の手駒にして次の補充でもう一度探す
  - 手順どおりの盤面になっていなければ（違う置き方をしたら）、そこで計画はおしまい（探し直して助けない）
  - 以前あった「盤面が空のとき約60%で手順集（`allclear-library.js`）から配る」は無くした（序盤ずっと全消しになるため）。手順集はテスト用に残してある
  - 実際の見つかり方（確率 20% のときの実測。学習モードのおすすめで 28 局・2,800 手。`Game.stats`。今は 25% が基準で、出来で 10〜40%）: 引いた回数は補充の約11〜14%（手順の途中の補充では引かない）、探索 1 回で見つかるのは約 33〜55%（40ms の打ち切り）だが、見つかるまで次の補充でも探すので、引いた分の約95%は見つかる。手順が配られる補充（手順の 2 回目以降も含む）は、補充の約30〜39%
- ラインは縦と横の2種類で、**まったく同じルール**（盤面は対角線について対称）：
  - 縦N = 右から N 本目の列（N マス）。右端が縦1。斜辺側の端は**下端**
  - 横N = 下から N 本目の行（N マス）。下端が横1。斜辺側の端は**右端**
- ラインN が満杯（ちょうど N 個）になると発動：ラインごと通路へ抜け、ベルトコンベアのように流れる
  （縦は盤面の下を右へ、横は盤面の右を下へ）。斜辺側の端のブロックが右下の共通ゴールへ入り、
  残りは同じ種類の N-1 … 1 番ラインへ斜辺側の端から入る。入ったブロックは**ブロックか壁に当たる手前まで奥へ進む**
  （他のブロックは動かない）。ただし入る先のラインの**手前の端が埋まっている**ときは、一番近い空欄までのブロックを
  奥へ1マスずつ詰めて、空いた手前の端に入る。満杯のときだけ、そのブロックはゴールへ流れる。
- 処理順（1本発動するごとに盤面を再判定）：
  - 同じ向きの中では**番号が小さいライン**から
  - 縦と横の両方に満杯のラインがあるときは、それぞれの最小ラインから始めた場合を最後までシミュレーションして、次の順に選ぶ
    1. **詰まない向き**: まだトレイに残っている手駒が、全部置ける ＞ どれか1つは置ける ＞ 1つも置けない（詰み）
    2. **連鎖が大きくなる向き**
    3. それでも同じなら縦
    （トレイの最後の1個を置いたときは、残りの手駒が無いので 2 から。手駒の組み合わせを決めるときの読み・学習モードのおすすめ・
    仮置きの表示も、同じ決め方でシミュレーションする。`sim.js` の `nextActivation`）
- どのピースも置けなくなったらゲームオーバー。
  ゲームオーバー画面は、盤面も背景もぼかした上に、ゲームの部品（丸いピル・盤面と同じ色の半透明の面）と同じ作りのカードを 1 枚浮かべる。色は盤面の種類（宝石・ガラス・ホワイト・3D）に合わせる。
  カードの中は「置ける場所がない！」のピル・スコア・ベストのピル・最大連鎖とコンボのタイル・金色の「もう一度」・「結果をシェア」・ランキングと遊び方。下から順に少しずつ出てくる。
  判定自体は置いた瞬間（連鎖が確定した時点）で決まるが、「置ける場所がない！」画面は連鎖の再生が終わるまで出さない
  （連鎖の途中でも、まだ置いていないトレイのピースは掴んで動かせる。実際には置ける場所が無いので、離すとトレイへ戻る）。
- ルールは置いた瞬間に最後まで確定し、アニメーションは後から再生される。再生中でも次のピースを置ける。
  連鎖が進んでも再生は速くならない（どの連鎖も同じ速さ）。再生中に次のピースを持ち上げている間は、連鎖の再生をいつも 3 倍の速さにする
  （`HELD_SPEED`。以前は置くまでに追いつくよう速さを見直していた。下記）。再生中に置いたピースと連鎖の通り道が重ならなければ、連鎖をそのままの速さで再生する。
  重なるときは音と動きを残して 8 倍速にし、連鎖が通過してから新しいピースを表示する（ブロックが重なって見えるのを防ぐ）。
  追いつくまでは仮置きを出さず、落としたときもほぼ真下にしか吸い付かない（見えていない場所に置かれないように）。
  持っているだけなら速めない。盤面へ近づけているときだけ、今の近づく速さで盤面に届くまでの時間を見積もり、
  それまでに再生が終わらない分だけ速める（間に合うなら速めない。盤面の上ではもうすぐ置くものとして、盤面に着いてから 0.2 秒で終わる速さ。最大 2 倍）。
  残りの再生時間は、流れこむブロックが一番遠くまで進むマス数まで数えて見積もる（少なく見積もると途中で速まらなくなるので）。
  追いついたら仮置きを出す。
- 操作の細かいところ:
  - 持ち上げた指だけを追う（ほかの指で触っても、持っているピースは動かない・落ちない）
  - 指が離れたのが届かなかったとき（通知・アプリの切り替えなど）は、持っていたピースをトレイに戻す
  - 一時停止すると連鎖の再生も止まる（持っていたピースは戻す）
  - 連鎖の再生中にモードを切り替えても（= 新しいゲーム）、前のゲームの続き（ブロック・点数・ゲームオーバー）は出ない
  - ベストスコアはゲームオーバー・もう一度・モードの切り替え・アプリを閉じたときに残す（モードごとに別）

## 演出
- 配置音は **ガラスのコップをテーブルに置く音**（`src/ui/synth.js` の `glassBuffer`）: 縁の「カチッ」+ ガラスの共鳴
  （薄いガラスの曲げ振動の、整数でない部分音 1 : 2.83 : 5.42 : 8.77。基本は 2 つに割れてうなる）+ 底がテーブルに当たる低い「コツ」
  + ごく小さな再接触。コップの高さ違いの 4 種を順番に使い、ピースのマス数が多いほど低く重く鳴らす。
  着地は 240ms（ぴったりなら 290ms）。列から流れる間はブロックと盤面の大きさを固定し、同色の小さなかけらを添える。
- **シャラン**（`shalanBuffer`。バーチャイム = マークツリーの音）: 満杯になったラインの枠が光る瞬間に鳴る。長さの違う金属のバーを並べて吊るした
  楽器を指で 2 回なでたような、尖った高い「シャン、シャン」。1 回目は一番低いバー（約 1.1kHz）から最後のバーまで、半音ごとのバーを約 0.12 秒で
  順に叩いて（だんだん強く）、約 0.12 秒に「シャッ」とはじける。2 回目は最後のバーの 7 半音下から（約 0.2〜0.28 秒）、もう一度はじけて、
  最後のバー（「ン」）だけが約 1 秒、長く響く。硬く叩いた金属のバーの部分音 1 : 2.756 : 5.404 : 8.933（高い部分音を強く）に、棒どうしが
  擦れ合う「シャッ」（4〜9kHz の帯域雑音）と叩く瞬間の「チッ」を重ねる。最後のバーの高さは、ゴールの音と同じ音階の 3 オクターブ上
  （2〜4.5kHz）で、連鎖が進むほど高くなる（6 連鎖までは別の高さ）。ペンタトニックの音のバーは大きく長く、間の半音のバーは小さく短く
  鳴らす（最後に残るのは濁らない音）。高さが変わっても、長さと大きさは同じ（再生の速さで高さを変えると長さも変わるので、高さごとに合成する）。
  全消しは「シャンシャン、シャンシャン」の 2 回（2 回目は高い）、新記録のファンファーレは 1 回
- **鈴**（`bellBuffer`）: ゴール・手駒の補充・ぴったり・コンボ・褒め言葉・砕ける音・ファンファーレ・全消しの駆け上がりの「ピン」。以前は 200〜800Hz の
  正弦波・三角波だけで、1kHz 以上のエネルギーがほぼ 0 だった（スマホの小さなスピーカーは 500Hz 以下がほとんど出ないので、細く薄っぺらく聞こえた）。
  今は、基本・オクターブ上・金属の整数でない部分音（2.756 倍・5.404 倍）・胴の低い響き（0.5 倍）が、違う速さで消えていく鈴の波形
  （わずかにずれた対のうなり・短いこだま 2 つ・打った瞬間の「チッ」付き）。ゴールの音は 1 オクターブ上げた（555〜1865Hz。同じ音階）。
  高さごとに作らず、短 3 度おきの 11 個の波形を、再生の速さ ±9% 以内で合わせて鳴らす。聞こえる大きさ（耳の感度で重み付けした RMS）は前と同じ（0.99〜1.18 倍）で、
  響きは 1.5〜2 倍長い（−40dB まで 0.2 秒 → 0.3 秒ほど）。小さなスピーカーでは、低い連鎖のゴール・コンボ・褒め言葉が 1.6〜2.3 倍（約 4〜7dB）大きく聞こえる
- **音のセット**（`synth.js` の `KITS`: ガラス → 木琴 → オルゴール）: 置く音・シャラン・鈴（ゴール・手駒の補充・ぴったり・コンボ・褒め言葉・砕ける音・
  ファンファーレ・全消しの駆け上がり）の楽器が、**スコアが 1000 点（`KIT_EVERY`）進むごとに順に替わる**（`kitForScore`。3000 点で最初へ戻る）。
  ターンの始まりのスコアで決めるので、連鎖の途中で楽器は替わらない。持ち上げ・なぞる・置けない・解放などの短い操作の音は、どのセットも同じ。
  新しいゲームはガラスから。途中から再開したときは、そのスコアのセットから。チュートリアルは常にガラス
  - **ガラス**: 今までの、ガラスのコップ・バーチャイム・鈴（上）
  - **木琴**（マリンバ。`marimbaPlace` / `marimbaRun` / `marimbaNote`）: ローズウッドの棒を撥で叩く。部分音は基本の 1 : 約 4 : 約 10 倍
    （棒を削って調律した、整数に近い比 → 音の高さがはっきりして、丸く温かい）+ 共鳴管の低い響き（0.5 倍）+ 撥が木に当たる「コッ」。
    置く音は「ポコッ」（ミ・ソ・レ・ラの 4 種）、シャランは棒を駆け上がる「コロロン、コロン」（最後の棒の高さはバーチャイムの 1 オクターブ下）、鈴は毛糸の撥の 1 音
  - **オルゴール**（`musicBoxPlace` / `musicBoxRun` / `musicBoxNote`）: 鋼のくしの歯（片持ち梁）をピンが弾く。部分音は基本の 1 : 6.27 : 17.55 倍
    （金属の棒の 2.756 倍より、ずっと高く離れる → 細く澄んだ基本に、すぐ消える高い「チリン」）+ ピンが弾く「ぴっ」+ 木の箱の胴鳴り。
    置く音は「ポロン」（ド・レ・ラ・ミの 4 種）、シャランは歯を駆け上がる「ティロリン、ティロリン」（最後の歯の高さはバーチャイムと同じ）、鈴は歯 1 本
  - どのセットも、耳に聞こえる大きさ（耳の感度 A 特性 + 小さなスピーカー風の低音カットで重み付けした大きさ）をガラスにそろえた
    （置く音は 4 種とも ±0.2dB、鈴 11 段は ±1.2dB、シャラン 6 種は ±1.0dB 以内。テストで確認）。合成も軽い（1 セットぶん 40ms 前後）。
    波形は、いまのセットと次に替わるセットだけ、起動後の空き時間に先に作り、使わないセットは捨てる
- ガラス・シャラン・鈴の波形は、DOM にも WebAudio にも依存しない純粋な計算（モーダル合成: 消えていく正弦波の足し合わせ + 打撃の短いノイズ。
  乱数は固定シードで毎回同じ音）で、1 回だけ作って `AudioBuffer` にして使い回す（セットごとに 置く音 4 種 + シャラン 6 種の高さ + 鈴 11 段。起動後の空き時間に
  1 つずつ先に作る。`Sfx.warm`）。1 回の発音が 1 ボイスなので、同時発音の枠（40）を使い切らない。高い響きは、ほかの音を丸めている
  3.8kHz のローパスを通さない「明るい出口」（9.5kHz のローパス。音量・ミュートは同じ）から出す
- 連鎖音は2オクターブのペンタトニック。高い音を同じ周波数へ切りそろえず、オクターブを下げて和音の違いを保つ。
  長い連鎖は旋律を繰り返しながら和音を足す。褒め言葉の和音は段階が上がったときだけ鳴らす。
- ホバー・着地音は短い間隔でまとめ、同時発音は40音まで。ミュートは予約した音も停止し、端末に設定を保存する。
  一時停止では盤面内の演出と遅延処理も止まり、リセットすると前のゲームの音・かけら・遅延処理を破棄する。
  詳しい分析・演出の数値は [docs/feedback-design.md](docs/feedback-design.md)。
- デザインの方針: 盤面・ブロック・文字・背景が1つの絵として馴染むことを優先する
  - 盤面の中の演出は**動き**（弾む・縮む・揺れる・寄る）と、**ブロックと同じ塗りのもの**（宝石のかけら・マスに満ちる色）、
    それに**ラインの光**（満杯の枠・通り過ぎた跡の白い縁・先のとがった星。下記）。ぼんやり丸く光る粒・輪・フレア・火の粉・花火・紙吹雪や
    画面のフラッシュは使わない（宝石の陰影と合わず、浮いて見えるので）。光はくっきりした形で、ほんの短い間だけ
  - 宝石・色の塊は半透明にしない（背景と混ざって濁るので）。出し入れは大きさ（scale）で行い、濃さは変えない。薄れて消えるのは光（枠・星）だけ
  - 文字（スコア・連鎖・COMBO・得点）はすべてベタ塗り + 真下への薄い影（`--ts`）。ふち取り・光のにじみ・グラデーションの文字は使わない
  - 背景の色は、白い固定の文字・ボタンが読めるよう、明るさ（OKLCH の L）を色相によらずそろえたまま色相だけを回す（下記）。動画映りのために、以前より明るい（下記）。盤面の土台（プレート）も、背景と一緒に同じ色相へ変わる
- ブロックの動きはゆっくりめ（1マス 60ms。連鎖が進んでも速くしない）:
  - 発動の直前にラインのブロックがぎゅっと縮み、ラインの番号が弾む「溜め」（150ms）→ 解放
  - 列からの移動中は盤面を固定する。溜めの縮みは宝石の面だけに掛け、座標を持つ親要素は拡縮しない
  - 配られるブロックが入っていく列の番号の後ろにブロックの色の丸が出て、止まった瞬間に小さな音（ブロックは弾ませない）
  - 発動したラインのマスには、列車が通り過ぎた順にブロックの色が満ちて引いていく（マスのくぼみの底に色が溜まる見え方）
  - **ラインが満杯になった瞬間**（溜めの始まり。連鎖の 2 番目以降は発動の始まり。`Renderer.lineGlow`）: そのラインの枠が白く光り
    （ふちは白、外側と内側にブロックの明るい色のにじみ）、光の帯が流れる向きに走り抜け、星（先のとがった四方の星 + 小さな斜めの星。
    `src/ui/sparkles.js`）が順にきらきらとまたたく。シャランの音もここ。溜めと発動で同じラインに二重に出さない
  - **ブロックが通り過ぎた跡**（`Renderer.trail`）: 列車の後ろが抜けたマスの縁が白く光って 0.3 秒で引き、星が 1 つまたたく。
    ラインの外（斜辺と通路の間・通路の入り口）も、ゴールの手前まで 9 マス続く（光る要素は動いているブロックより下 = ブロックの後ろ）。
    ゴールに入る瞬間は、ゴールの回りに星がはじける（`goalSparkle`）
  - ゴールに入るブロックは縮んで消え、ゴールがぽんと弾んで中が入ったブロックの色で満ちる。ゴールから宝石のかけら
    （ブロックと同じ4つのふちの面とテーブル面・同じ光の向き。回さない）が上へはじけて落ちる。
    得点が浮かぶ（白 → 3連鎖〜 金 → 5連鎖〜 桃）。スコアは数字がくるくる増える
- 2連鎖以上で `n CHAIN` と `Good! → Great! → Excellent! → Amazing! → Unbelievable!`（段階ごとに文字の色と和音が変わる。
  Unbelievable は文字の色がブロックの色を順に移る）。ふち取りが無くてもブロックに埋もれないよう、盤面の上の空いた所に出す。
  大きい文字は1文字ずつ上から落ちてきて弾み、褒め言葉はそのあと下からせり上がる
- 連続発動ターンは `COMBO n`（白と金の文字）
- **背景の色**（`src/ui/ambient.js`）: ゲームの始まりは青（`#3a6adf` / `#4479f2`）。以前の青（`#2451c4`）は全体に暗く、画面を録画した動画で映えなかったので、
  色相と鮮やかさはそのまま、明るさ（OKLCH の L）を 0.478 → 0.558 に上げた（見た目の明るさ = 相対輝度は約 1.6 倍。`src/ui/styles.css` の `--bg` / `--bg-hi`・`index.html` と
  `manifest.webmanifest` の青・結果カードの背景も同じ）。白い固定のスコア・ボタン・文字が読めるよう、明るさは色相によらずそろえたまま色相だけを回す
  （白との対比は縁で 4 以上〔青で 4.9〕、中央の明るい所でも 3.6 以上。以前は 6〜7 と 5 前後。輝度の高い緑〜青緑の淡い段だけ、中央の対比が 3.6 を下回らないよう明るさを少し下げる）。
  同じ色相に「淡い（soft。+0.04）」「濃い（deep。−0.05。以前は −0.083 で暗すぎた）」の 2 段を足す。
  **ゆっくり変わり、並びは毎回ちがう**（決まった順に回り続けない）:
  - ふだんの色: 発動しない手が **8 回**続くたびに、**5 秒**かけて次の色へ（以前は 5 回・3 秒）。次の色は、向きと幅（45〜110°。向きは 65% そのまま・35% 反対）を毎回
    ばらして選び（`nextHue`）、最近の 4 色の 40° 以内には落ち着かない（決まらなければ幅を広げる）。濃さも毎回選ぶ（標準 45%・淡い 30%・濃い 25%。標準以外は続けて同じにしない。`nextTone`）
  - コンボ: **コンボが始まるたびに**、色の進み方（向き ±・1 つ増えるごとの幅 22〜38°・5 の倍数での大きな幅 48〜88°・濃さの回り始め）を引き直す（`comboStyle`）。
    **2.2 秒**かけてグラデーション（以前は 1.4 秒）。5・10・15… は一気に（**0.45 秒**。以前は 0.16 秒）
  - Amazing 以上の連鎖は一気に（0.45 秒）別の明るい色へ（向きと幅はばらす。2.2 秒見せて 3 秒かけて戻る）、全消しは色相をぐるりと 1 周
    （向きはばらす。3.2 秒）して次のふだんの色へ、新記録は一気に別の明るい色へ。お祝いの色を見せている間は、手が置かれても上書きしない
  - 黄〜黄緑（80〜138°）は同じ明るさだとオリーブ色に濁るので、落ち着く先にはしない（途中を通り過ぎるだけ）。
    リスタートで今の青に戻る。チュートリアル中は変えない。動きを減らす設定では、小さな重ねを 1 回、0.7 秒以上かけて（急な点滅にしない）
  - 動かすのは opacity だけ: 色ごとの全面グラデーションの層（最大 4 枚）の新しい色を上に重ね、覆い終わった下の層は外す。
    遠い色へのグラデーションは 40° 以内の小さな重ねを続ける（遠い色を一度に混ぜると灰色に濁るので）。
    **色が落ち着いている間は全面の層を使わず、背景は `body` に直接描く**（全面の層が 1 枚あるだけで、操作中の毎フレームの合成が重くなるので。ドラッグ中の
    メインスレッドの仕事が約 1 割減った）。色が変わり始めるときだけ、今の色の層を下に敷いて（`lift`）新しい色を重ね、覆い終わったら `body` に描き直して
    層を片づける（`settleOn`）。ブラウザの上のバー（`theme-color`）と、コンボ・ピンチ・色の変化の同系色（CSS 変数 `--amb-glow`。
    ルート `:root` ではなく、使う要素 `#fever` / `#danger` / `#sceneTint` にだけ書く。ルートに書くと、色が変わるたびに画面の全要素のスタイルを計算し直して引っかかった）も背景の色相に合わせる
  - **盤面の土台**（マスの下の土台・くぼみ・縁の線・盤面のまわりの光と影。`.well-set`）も、背景と同じ色相・同じ濃さの段・同じ瞬間・同じ長さで変わる
    （`Ambient.bindBoard`）。色は今の青の土台の明るさ・鮮やかさ・色相のずれをそのまま保って、背景と同じ角度だけ色相を回したもの
    （背景より少し暗い板に、もっと暗いくぼみ、という見え方は、どの色でも同じ。背景を明るくしたのに合わせて、最初の青の土台も明るさを 0.06 上げた〔背景ほど上げないのは、土台が明るすぎるとブロックが浮かなくなるので〕）。最初は今の青のまま（`.well-set` の値そのもの）。背景と同じく、土台の絵を
    5 枚重ねて opacity だけで切り替える（毎フレームの描き直しは起きない）。スコア・ボタン・ゴールの枠・ブロックの色は変えない
- **ALL CLEAR**: 画面を覆う演出は使わない（盤面の中だけ。`Renderer.allClearBlast`）。`n CHAIN` と同じ場所に `ALL CLEAR!` の文字（`t5`。虹色）と
  `BONUS +n`。空になった全マスに、盤面の中心から輪になって順に7色の宝石（盤面のブロックと同じ `.block` の塗り）がぽんと満ち、
  同じ順に砕けて小さくなりながら、ブロックと同じ塗りのかけらを散らす。砕けるたびに盤面がぐっと寄る。
  宝石は半透明にせず大きさだけで出し入れする。遅い端末・動きを減らす設定では、マスに色が満ちるだけ
- 画面全体の演出（`src/ui/scenes.js`。奥の色の変化と、新記録の風船だけ。それ以外は画面を覆わない）:
  - **Amazing 以上の連鎖・COMBO 5・10・15…**: 背景の色相に合わせた薄い同系色（`--amb-glow`）を重ねる
    （連鎖は 12・16…でもう一度。続けて重ならないよう 1.1 秒あける）。背景そのものの色も一気に変わる（上記）
  - **NEW BEST**: 薄い同系色を重ね、ベストスコアの枠がぽんと弾んで7色のかけらがはじけ、画面の左下・右下から
    かけらが2回噴き上がって落ちてくる。`n CHAIN` と同じ場所に `NEW BEST!` の文字（`t5`）・ファンファーレ
  - 画面全体で飛び散るものも、盤面のかけらと同じ絵（`shards.js` の `gemSprite`: ブロックと同じ4つのふちの面とテーブル面・
    左上からの光・右下へ落ちる小さな影。回さない）。薄くせず、小さくなって消える
  - 重くしないために: 色の変化は1回だけ描いた 400px の絵を拡大し、opacity と transform だけで動かす。
    演出を描いている間のフレーム時間を測り、遅い端末では半透明の層や粒の数を減らす（`Scenes.quality`）
- 仮置き（指に付けたまま盤面に重ねる）: 消える列のブロックを持っているピースの色に塗り替えて白いふちで脈打たせ、
  その列の番号にも色の丸が出て、GOAL が弾む。消える場所に入った瞬間に上昇音と軽い振動、ピースの上に `CLEAR` / `⚡n CHAIN`
- 穴・凹みにはまる場所に持っていくと、仮置きがきゅっと吸い込まれるように収まる。ぴったり・長方形の場所ではさらに濃くなって
  カチッと鳴る。置くと `PERFECT FIT!`（穴）/ `NICE FIT!`（長方形）とボーナス点、カチッ + 上がる2音。
  はまること自体が気持ちよさなので、枠などの印は出さず、長方形ができてもブロックは消えない
- 盤面が混んだり、置けない手駒があるピンチのときは画面の縁が暖色でゆっくり脈打つ（発動で空くと消える）
- ゲーム中にベストスコアを超えた瞬間にベストスコアの枠が金色になって弾む
- 長い連鎖でもカクつかないように:
  - 同時にゴールへ入るブロックの演出と音は1回にまとめる
  - **小さな演出（星・宝石のかけら・ラインの光の跡）は、粒ごとに要素を作らず canvas に描く**（`src/ui/fx2d.js` の `FxCanvas`。星は `sparkles.js`、かけらは `shards.js`、
    光の跡は `rims.js`）。粒を 1 つずつ要素にして Web Animations で動かすと、ブロックを動かす `requestAnimationFrame` が回っている間は、動いている粒の
    数だけ毎フレーム、スタイルの計算・レイヤーの更新が主スレッドに来る（粒 40 個で、何も動かさないときの約 5 倍の仕事。測り方は docs/feedback-design.md）。
    canvas（GPU で描く）なら粒の数によらず 1 枚の層と `drawImage` だけで、粒に使う仕事は同じ 60 個で約 1/7。色ごとに 1 回だけ描いた小さな絵（星 64px・宝石 64px・光の枠）を、拡大・回転・濃さを変えて貼る。
    何も描いていない間は canvas を画面から外す（`hidden`）ので、層は残らない。星・かけらはブロックの前（`.fx2`）、光の跡は以前の光る要素と同じ重なり（動いているブロックの後ろ。`#fxLayer`）。
    動き（ease-out・区切りごとの直線・放物線）は以前の Web Animations と同じ式（`sparkPose` / `shardPose` / `rimPose`）。同時に 星 36 個・かけら 14 個（全消しは 42）まで。
    一時停止は canvas の時計も止める。GPU を使わない描画（ソフトウェア。仮想マシンなど）では、canvas の中身を書き換えるたびに画面の面積ぶんの写しが要り、面積と密度の 2 乗に比例して重くなるので、
    起動後の空き時間に WebGL の描画装置の名前で見分け（`softwareRendering`）、そのときだけ描く細かさを 1 倍に下げ、2 コマに 1 回の更新（30fps。動きは時刻で決まるので、速さは同じで、なめらかさだけが少し落ちる）にする
  - マスに満ちる色の要素（36 個）は、色が満ちている間だけ画面に出す（常に 36 個あると、何も動いていなくても描画の仕事が増える）
  - ブロックが動いている間のフレーム時間を測り、遅い端末では かけら・波打ち・1文字ずつの文字・マスに満ちる色 を自動で減らす（`Renderer.q`）
  - アニメーションのやり直しに `offsetWidth` を読む強制レイアウトは使わない（Web Animations か要素の差し替え）
  - 背景の変化（コンボ・ピンチ）は opacity と scale だけを動かす（filter や box-shadow を毎フレーム動かさない）
  - ラインの光: 星・通り過ぎた跡は canvas（上）。枠（`.line-glow`。1〜2 個）は opacity と scale だけ。遅い端末では、星（品質 0.6 未満）→ 跡の光（0.5 未満）の順に減らし、枠だけにする。
    動きを減らす設定では、枠がふわっと光って消えるだけ（帯・星・跡は出さない。音は鳴る）。早送りでは出さない。
    速い再生（再生待ちが溜まったとき）では枠の光も短くして、重ならないようにする
- 画面を止めないために（演出・ルール・ロジックの結果は変えずに）:
  - **手駒の決め方と学習モードのおすすめの総当たりは Web Worker で動かす**（`src/core/dealer-worker.js`。窓口は
    `src/ui/tray-dealer.js`、中身は `src/core/dealer.js` が `Game.spawnTray` / `advisor.bestMove` をそのまま呼ぶ）。
    手駒の探索は時間で打ち切る作りで 1 回に 100ms 近くかかることがあり、メインスレッドで動かすと置いた瞬間に画面が止まるため。
    決め方のコード・時間の上限は同じで、補充の手駒は決まったらトレイに出る（それまでトレイは空。詰みの判定は届いてから）。
    Worker が使えない・読み込めない環境では、同じ処理をメインスレッドで行う。同じ乱数・同じ時間の進み方なら、
    同期で決めた場合とまったく同じ進行になることをテストで確認している
  - 虹色の文字（`t5`）の色の移り変わりは、文字が見えている間だけ（無限にすると、消えた後も毎フレーム色の計算と描き直しが続く）
  - ドラッグ中は盤面の位置を読んでからピースを動かす（書いてから読むと、動かすたびにレイアウトの計算し直しになる）。
    仮置きの情報（消えるライン・連鎖数）と、縦横どちらを先に発動するかの読みは、探索用の軽い盤面（`sim.js`）で計算する
    （結果は盤面本体と同じ。テストで確認）
  - 同じ値のスタイル・文字は書き直さない。トレイの寸法は大きさが変わったときだけ測る。置いたブロックの弾みのやり直しに強制レイアウトを使わない
  - 画面いっぱいの層は、使っていない間は画面から外す: 新記録の風船の canvas（`#sceneFront`）・ピンチの縁（`#danger`）・コンボの光（`#fever`）は `hidden`
    （opacity 0 でも置いてあるだけで、毎フレームの合成に画面 1 枚ぶんの層が残る。出るときは opacity 0 で描かせてからふわっと出し、消えるときは薄くなってから外す。`setVeil`）。
    背景の層も、色が落ち着いている間は使わない（上の「背景の色」）
  - 同系色の変数 `--amb-glow` は、ルートではなく使う要素にだけ書く（ルートに書くと、色が変わるたびに画面の全要素のスタイルを計算し直す）
  - ドラッグ中のピースは `transform: translate(...)` だけで動かし（`will-change: transform`）、`left` / `top` は書かない（書くとそのたびにレイアウトと描き直し）
  - 星・かけら・光の枠の絵と、鈴・シャラン・置く音の波形は、起動後の空き時間に 1 つずつ作っておく（最初に出る瞬間に止まらないように）

## チュートリアル（はじめて遊ぶ人向け）
- はじめて開いたとき（ベストスコアも途中の保存も無い）に、遊びながらルールを覚える5手が始まる。一時停止の「遊び方」からもう一度見られる
  1. ピースをつかんで置く
  2. ラインは番号の数だけ入ると満杯 → 発動。1個は GOAL、残りは小さい番号のラインへ1個ずつ流れこむ（縦3。2連鎖）
  3. ブロックの動き方: 横のラインも同じルール。流れこんだブロックは奥へ進み、ブロックか壁の手前で止まる（横5）
  4. 押しこみ: 入る先のラインの入口（斜辺側の端）がふさがっていると、中のブロックを奥へ1マス押して入る（縦4。4連鎖）
  5. 連鎖のコツ: 横1〜4 を「あと1個」にしておき（番号を光らせる）、横5 を満杯にすると次々に満杯になる（10連鎖）
  6. 3つ置くと次の3つが来る・置けなくなったらおしまい・コツのまとめ →「はじめる」で本番のゲーム
- **2〜4 はブロックの動きを本物の盤面で1つずつ見せる**（`explain`。再生をゆっくりにし、途中で止めて説明する）:
  - 満杯になったラインのマスを金色の枠で囲み、番号を光らせる（少し見せたら自動で進む）
  - ラインのブロックが通路へ流れ、先頭の1個が GOAL に入ったところで止める（GOAL が弾む）
  - 残りのブロックが止まるマスに白い枠（中にそのブロックの色）を出し、入る先のラインの番号をブロックの色で光らせる。
    押しこまれるブロックの行き先にも枠を出す。そこから入っていくのを見せる
  - 止まっている間は説明の下に「次へ」が出て、画面のどこをタップしても進む（出した直後のタップは数えない）。
    再生が終わったら まとめ を出し、タップで次のステップへ
  - 止める場所は `Renderer.playStep` の `pause`（普段の再生では使わない）
- 置く場所は金色の枠で示し、指の絵がトレイのピースを運んで見せる。決めた場所にしか置けない（近くで離せば吸い付く）

## 対戦（`src/core/battle.js` ルール / `src/ui/versus.js` 画面 / `src/ui/net.js` 通信 / `functions/api/battle.js` サーバー）
ぷよぷよと同じく、連鎖で相手に「おじゃま」を送り合い、置ける場所がなくなったほうの負け。
- **おじゃまブロック**（`createGarbage`）: 数字を書いた 1×1 の灰色のブロック。**2 連鎖以上**すると、**連鎖の数を書いたおじゃまが 1 個**相手へ飛ぶ（5 連鎖なら「5」）。
  1 連鎖では送らない（ぷよぷよでも小さな消し方ではおじゃまは送られない）。**全消しは +5**（ぷよぷよの全消しボーナス。最後のおじゃまが連鎖で消えて盤面が空になっても全消し）
- **おじゃまのルール**: 動かない・その上には置けない・**入っているラインは満杯にならない（発動しない）**。流れこむブロックにとっては壁と同じ（手前で止まる。押しこみもおじゃまの手前まで。
  手前の端からおじゃままでに空欄が無ければ、満杯と同じくゴールへ流れる。`Board.insertBottom` / `sim.js` 同じ結果になることをテストで確認）
- **削る**: 自分が連鎖すると、盤面のおじゃまの数字が**全部、連鎖の数だけ減り**、0 になると砕けて消える（相談のうえで決めたルール。1 連鎖でも 1 減る）。
  連鎖の途中は、1 連鎖ごとにおじゃまの上に赤いピルで「−1」「−2」…と出し（`garbageTick`。相手の盤面も同じ）、ターンの終わりにその数だけ数字が減る
- **予告**（ぷよぷよの予告ぷよ）: 送られたおじゃまは、まず自分の盤面の上に並ぶ。相手の連鎖がまだ再生中のあいだは小さく薄く（届くまでの時間は、相手の連鎖の再生時間 `playDuration`）、
  終わると大きくなって揺れ、**すぐ落ちてくる**（置くのを待たない）。1 回に落ちるのは 5 個まで（`DROP_MAX`。ぷよぷよの 1 回 30 個まで。残りは、その落ちる動きが終わったらすぐ）
- **自分の連鎖の途中に届いたおじゃま**は、その連鎖が終わったらすぐ落ちる（`BattleSide` の `busy` = 自分の連鎖・おじゃまの落ちる動きを再生しているか）。
  盤面の上までふさがって落とせなかったときは、次に置いて盤面が変わるまで予告に残る。
  予告のおじゃまを連鎖で打ち消す「相殺」は使わない（削るルールと同じことをしていて分かりにくいので。`OFFSET_PENDING` を true にすると、予告も連鎖の数だけ削れる）
- **落ちてくる演出**（`Renderer.garbageLand`。自分の盤面も相手の盤面も同じ）: 落ち始める前に**字幕**「おじゃま ×3 / 数字 7・3・3」（赤。3 個以上か数字の合計 10 以上は大きく）・
  画面の縁の赤い光・盤面の小さな揺れ・低い警告音（`garbageIncoming`）→ 1 個ずつずらして、火花の尾を引いて落ち（重力で加速）→ 着地は盤面が沈んで弾む・画面が揺れる・衝撃の輪・かけら・低い「ずしん」
  （数字が大きい・個数が多いほど強い）。演出の長さは `dropPlayMs`（`core/battle.js`）で画面・相手の盤面・シミュレーションが同じ見積もり
- **落ち方**（`dropPath`）: 盤面の上から落ちてきて、直角が下の V 字の入れ物の一番低いところに積もる（画面の縦の列を落ち、下の 2 辺のどちらかが空いていれば斜めにすべる。
  ブロックをすり抜けない＝上からふさがれた穴には入らない）。止まる場所の候補のうち、トレイの手駒が置けるままの場所を先に選ぶ
  （たまたま手駒の入る場所だけがふさがって、盤面がまだ空いているのに負けることがないように。盤面が本当に混んできたら負ける）
- **マージンタイム**（ぷよぷよと同じく、長引いたら強くなる）: 1 分 30 秒を過ぎると 1 回に送るおじゃまが 2 個になり、そこから 20 秒ごとに 1 個ずつ増える（5 個まで。どれにも連鎖の数を書く）。
  連鎖のたびに盤面のおじゃまが全部削れるので、数字より個数を増やすほうが決着がつく
- **手駒は 2 人とも同じ順番**で出る（種から決まる乱数 `seededRandom`。CPU 対戦は 1 戦ごとにでたらめな種、オンラインは部屋の id と何戦目かから作る `seedOf`。2 人とも同じ種）。
  **使った枠には、すぐ次の手駒が入る**（3 つ使い切るのを待たない。`Game.placePiece` の `refillSlot`）。手駒は盤面に合わせて選ばず、決まった出やすさで出す。
  すぐ補充されるので、置きにくい大きな形は枠に残りつづけて詰まりやすい。対戦だけ大きな形を少なめにする（`BATTLE_TYPE_SCALE`: 3×3 は出ない・5 マスの L と十字は 0.3 倍・2×3 と 5 マスの直線と W は 0.5 倍）
- **連鎖の再生が終わるまで次のピースは置けない**（CPU 対戦・オンラインとも。手駒が少し薄くなる）。連鎖の再生はいつも、ピースを持っているときと同じ速さ（3 倍。`BATTLE_SPEED`）。
  相手の小さな盤面も同じ速さで再生し、CPU も自分の連鎖が終わってから考えて置く。どちらの画面でも連鎖の長さが同じになり、送ったおじゃま・届いたおじゃまが順番どおりにきれいに並ぶ
- 数値は CPU 同士のシミュレーション（`node scripts/sim-battle.mjs`）で決めた: 少しまちがえる CPU 同士（`miss=0.1`）で 1 戦のまん中がおよそ 1 分半
  （大きな形を少なめにする前は 50 秒ほどで、ほとんどが盤面が半分ほどのうちに手駒が詰まって終わった）。
  最初は（連鎖中も置けたころ）「自分の連鎖の再生中は落ちない」にしていたが、再生がほとんど途切れず、15 分たっても 1 個も落ちず決着しなかった。
  今は連鎖の再生が終わるまで置けないので、連鎖と連鎖の間におじゃまが落ちる。
  マージンタイムで数字を大きくするだけでも決着しなかった（数字は連鎖のたびに削れるので）。
  予告も連鎖で削る（相殺。`offset=1`）と、予告のうちにほとんど消えてしまい、6 戦とも 15 分で決着しなかった（盤面のおじゃまは多くて 1 個）
- **画面**（スマホの縦持ちなど）: 相手の盤面を自分の盤面の上に、**同じ大きさ**で並べる（半分ずつ。`versus.js` の `layout` が、2 つの盤面がちょうど収まるマスの大きさを決める。
  タブレットの横向きは自分の盤面の右に並べる）。名前・時計・予告は、それぞれの盤面の左上（通路の番号の外側の空いたところ）に重ねる。対戦中は手駒の欄を低くする。
  相手の盤面（`opp-board.js`）は**自分の盤面と同じ描き方**（`Renderer` をもう 1 つ。盤面の種類・背景に合わせて変わる土台の色・宝石・通路の番号・ゴール・連鎖の文字と動き・おじゃまの落ち方と「−1」まで同じ。
  音は鳴らさない。3D のときだけ、3D の canvas は自分の盤面 1 つしか描けないので、相手の盤面は宝石の見た目）。相手が置いたターンを、相手の画面と同じ速さ・同じ長さで再生する:
  置いたブロックが弾む → 満杯のラインが縮んで抜ける → 残りが入る先へすべりこむ → おじゃまの数字が減る。おじゃまは上から落ちてくる）。
  相手の名前の横には相手の予告、自分の名前の横には自分の予告。経過時間と、マージンタイムの「おじゃま ×2」。タブレットの横向きでは左の列に名前と予告
- **流れ**: 3・2・1・GO（鈴の音）→ 対戦 → 結果のカード（ゲームオーバーと同じ作り。WIN! / LOSE… / DRAW、「vs 相手」、通算の勝ち負け、最大連鎖・送ったおじゃま・消したおじゃま）→「もう一度」（同じ相手と）か「ホームへ」
- **演出**: 送ると、連鎖が見え終わるころに数字つきの灰色の宝石が自分のゴールから相手の予告へ飛んでいく（光の玉は使わない）。届いたおじゃまは相手の盤面から自分の予告へ。
  落ちると、つぶれて弾み、盤面が沈み、灰色のかけら。数字が減るとぽんと弾み（残り 2 以下は金色）、0 になると砕けて星がまたたく。
  3D では、くもった灰色のガラスの立方体（おじゃまどうしはつながない）に 2D の数字を重ねる
- **音**（どれも今の音のセットの鈴・置く音・ガラスで作る。ガラスの盤面ではコップの音）: 予告に届いた（低めの鈴が 2 つ下がる）・積もった（置く音を低く重く + 胴鳴り）・
  数字が減った（軽く上がる鈴）・砕けた（砕ける音 + 上がる鈴）・送った（上へ抜ける風 + 鈴）・相手が見つかった・カウントダウン・GO（和音 + シャラン）・勝ち（ファンファーレ）・負け
- **CPU**（よわい・ふつう・つよい。`CPU_LEVELS`）: 学習モードのおすすめ（`advisor.bestMove` の全部の手の順位）で置く。強さは考える時間（よわい 2.7〜4.3 秒・ふつう 1.8〜2.9 秒・つよい 1.0〜1.7 秒）と、
  一番良い手を選ぶ割合（残りは詰まない手の上のほうからでたらめに）。手駒の決め方・おすすめの総当たりは、自分とは別の Web Worker。CPU との対戦は一時停止できる
- 戦績（CPU の強さごと・オンライン）は端末に残し（`blockmancala-versus`）、ホームの対戦の画面に出す。対戦ではベストスコア・記録・ランキング・途中の保存は使わない（ひとりでの続きは残る）

### オンライン対戦
- **だれかと対戦**（同じ時に探している人どうし）と、**あいことば**（4 けたの数字の部屋を作り、友だちが入る）。なまえは世界ランキングと同じもの
- サーバー（`functions/api/battle.js`。世界ランキングと同じ D1 の `DB` を使う。表 `battle_rooms` / `battle_events` は初めて使うときに作る。**追加の準備は無し**）は、
  相手を見つけることと、2 人の間でメッセージを渡すことだけ（ゲームはそれぞれの端末で動く）。2 人が同時に部屋を作ったら新しいほうが古いほうへ移る。12 秒来なくなった人はいないものとし、2 時間たった部屋は消す
- 見つかったら、端末どうしを **WebRTC でじかにつなぐ**（STUN は Cloudflare と Google。つなぐための情報もサーバーを通す）。つながらないネットワークでは、**サーバーの中継（長めの poll）**で続ける。
  どちらの道でも、メッセージは送った順に 1 回ずつ届く（番号と ack。道が切り替わったら、まだ届いたと言われていないものを送り直す。`net.js`）。URL に `?relay` を付けると中継だけで試せる
- 送るもの: 置いた手（形・場所・残りの手駒）と、そのあとの盤面（短い文字。`packBoard`）/ おじゃま（数字・個数・相手の連鎖が終わるまでの時間）/ 落ちたおじゃまの場所 / 予告 / 負け。
  相手の画面は、置いた手と残りの手駒から同じルールで連鎖を作り直して再生する（`Game.mirror`。毎回の盤面と比べて、食い違ったら届いた盤面に合わせる）
- 先に置けなくなったほうの負け（ほぼ同時＝0.3 秒以内なら引き分け）。相手が出ていった・15 秒何も届かない → 勝ち（「相手が対戦をやめました」/「相手との通信が切れました」）。
  「もう一度」は 2 人とも押したら始まる
- 連鎖の速さ・連鎖中は置けないルールは、CPU 対戦と同じ（上の「対戦」）。通信の約束（`PROTOCOL`）は 2（同じ順番の手駒にしたとき上げた。ちがう版どうしは「バージョンがちがいます」）

### レート戦（オンライン）
- ホームの対戦の「レート戦」（金色。今のレートも出る）。レート戦どうしで相手を探す（だれかと（フリー）とは別）。**1000 から**、シーズンごとに別
- 増減はイロレーティング（K = 32。`rateDelta`）で、**勝った人が +d、負けた人が −d（2人を足すとかならず 0）**。同じレートどうしなら ±16、強い相手に勝つほど多く増える。引き分けはレートの差のぶんだけ動く
- 結果はサーバー（`functions/api/battle.js` の `result`）が 1 回だけ反映する: 2 人の知らせが合ったとき / 負けた本人が「負け」と知らせたとき / 勝った人の相手がもういないとき（12 秒来ない）。
  2 人の知らせが食い違ったら、その対戦は数えない。**途中でやめると負け**（ホームへ戻るとき「負け」を知らせる）。始まる前に相手がいなくなったら動かない
- 結果のカードに「レート 1000 → 1016 +16」。「もう一度さがす」で新しい相手を探す（レート戦は 1 戦ずつ）。レートランキングはランキングの「レート」

## スコア
- 置いたマス ×1、ゴールに入った1個 ×100（連鎖・コンボの倍率を掛ける前の基本点。シーズン1は 90）
- **ぴったりボーナス**: 穴にぴったり置くと、置いたマス1つにつき +25（`SCORE_PER_PERFECT_FIT_CELL`）
- **長方形ボーナス**: 置いて長方形がそろうと、長方形のマス1つにつき +10（`SCORE_PER_RECT_CELL`。ぴったりと両方なら足す）
- 連鎖倍率（シーズン2で少し上げた）: 2連鎖 ×2 → 3連鎖 ×4 → 4連鎖 ×6 → 5連鎖 ×10 → 6連鎖 ×14 → … → 12連鎖 ×60 → そのあとも1連鎖ごとに +12（**上限なし**。13連鎖 ×72、20連鎖 ×156）
- 連続発動ターン(COMBO)倍率（シーズン2で下げた）: COMBO 1 つごとに **×1.1 を掛けていく**（COMBO 2 = ×1.1、3 = ×1.21、5 ≒ ×1.46、12 ≒ ×2.85）、**上限なし**。連鎖倍率と掛け合わせる。
  シーズン1は COMBO 1 つごとに ×1.3 を掛けていく倍率で、長いコンボで点数が何千倍にもなり、ランキングがインフレしたので ×1.1 に下げた
  - COMBO = 置くたびに何かが発動した手の連続数。発動しない手を置くと途切れる

## 記録
- シーズンごとに、ベストスコア・**最大連鎖**・**最大コンボ**を端末に残す（ベストスコアと同じ時に残す。チュートリアルは残さない。シーズン2の記録の名前は `-s2` で終わる。
  シーズン1の途中のゲームは、スコアの計算がちがうので続けない）
- 端末に残す記録の名前はすべて `blockmancala-` で始まる（ゲーム名にそろえた）。前の名前（`stair-mancala-`）で残っている記録は、
  起動したときに新しい名前へ移してから消す（新しい名前がもうあればそちらを残す。`brand.js` の `migrateStorage`。テストで確認）
- ゲームオーバー画面に、このゲームの最大連鎖・最大コンボと、これまでの記録（超えたら `NEW RECORD!`）
- 一時停止画面にも記録を出す
- **ランキング**: 右上のトロフィーのボタン（ゲームオーバー画面の「ランキングを見る」・ホーム画面からも）。**世界** と **この端末** を選べる。**シーズン制**（今はシーズン2）
  - 世界は **ベスト**（このシーズンの自己ベスト）/ **累計**（このシーズンに遊んだゲームのスコアの合計とゲーム数）/ **レート**（オンライン対戦の「レート戦」。勝ち負けの数も）
  - 下の「シーズン1の結果を見る」で、同じ画面のままシーズン1の結果（世界のベストスコア・この端末）を見られる（もう記録は増えない）
- **世界ランキング**（`functions/api/ranking.js`。Cloudflare Pages Functions + D1）: **最下位まで**スクロールで見られる（50人ずつ、下の端が近づくと続きを読み足す）。自分の順位と参加人数も出す
  - シーズン1 は前からある表 `players`（そのまま残して見るだけ）。シーズン2〜は表 `season_players`（シーズン × 端末で 1 行。ベスト・累計・レート）。表と列は初めて使うときに API が作る（追加の準備は無し）
  - ひとりで遊んだゲームのスコアを送る（対戦は入らない）。送れなかった分（ベストと、累計に足す点数・ゲーム数）は端末に残し、次に送る。
    累計は送るたびに通し番号を付け、返事が届かずに送り直しても 2 回足されない。前のシーズンの古い画面から送られた記録はどこにも書かない
  - 端末ごとに id（32桁の16進。他の人には返さない）と名前（12文字まで）を持つ。**名前は自動では付けず、プレイを始める前に必ず決めてもらう**（はじめて開いたとき、または名前がまだ無いとき。決めるまで盤面には触れない・空では決められない・チュートリアルもそのあと）。決めるとすぐ世界ランキングに参加する。あとはランキング画面の「変更」で変えられる
  - ゲームは端末の中で動くので、送られた値が本物かまでは確かめられない（ありえない値だけはねる）
  - **準備**（Cloudflare のダッシュボードで1回だけ）: D1 のデータベースを作り（名前は自由）、Pages のプロジェクトの Settings → Bindings で **変数名 `DB`** としてつなぎ、もう一度デプロイする。表は初めて使うときに API が作る
  - `blockmancala.pages.dev` 以外（github.io など）で開いたときは、`blockmancala.pages.dev` の API を使う
  - **不適切な名前を隠す**（作成者だけ）: `admin.html`（`blockmancala.pages.dev/admin.html`。ゲームからはリンクしない）で、名前を「隠す」にできる。

  - **準備**（合言葉）: Pages の Settings → Variables and Secrets に **Secret として `ADMIN_KEY`（16文字以上）** を入れて、もう一度デプロイする。
    入れていない・短いときは、管理 API（`functions/api/admin.js`）は使えない（503）。管理画面は `Authorization: Bearer <ADMIN_KEY>` で呼ぶ（合言葉はこのタブを閉じるまでしか覚えない）
- **この端末のランキング**: 上位10ゲーム（シーズンごとに別。`blockmancala-ranking-s2`。シーズン1 は `blockmancala-ranking`。`src/core/ranking.js`）

  - シーズン1 の結果では、ランキングができる前のベストスコアを「以前の記録」として入れる
- **全消しボーナス** +5,000（そのターンの COMBO 倍率も掛ける）。`ALL CLEAR!` の下に `BONUS +n` を出し、GOAL の上に得点が浮かぶ
  - さらに全消しのあと **5手のあいだ、手に入るスコアすべてが ×1.5**（置いたマス・はまり方のボーナス・発動）。画面には出さない。
    もう一度全消しすると手数が5に戻る（倍率は重ねない）。途中の保存にも残る

## 画面
- **盤面の種類**: 右上の一時停止 →「盤面の種類」のプレビュー一覧から **宝石 / ガラス / ホワイト / 3D** を選ぶ。
  選んだ見た目は端末に保存し、次に開いたときも引き継ぐ。途中の盤面・手駒・スコアはそのまま。
  ガラスは紫の背景・継ぎ目のない半透明の盤面・丸い縁の反射・淡い色のピース。同色で辺が接しているマスをひとつの輪郭で描き、
  動くブロックは分かれて流れ、止まると再びつながる。
  ガラスと 3D の盤面には、マスの区切りに細くて薄い線を引く（3D ではブロックの真下には引かない）。手駒・ドラッグ中・結果のシェア画像も同じ質感になる。
  `src/ui/board-themes.js` / `board-themes.css` / `glass.js`。輪郭（穴・斜めの接点を含む）と設定保存は `node --test test/board-themes.test.mjs`。
- **ホワイト**（動画・スクショ映え用）: 白い背景・背景より少し色味の違う白一色の平らな盤面（影・くぼみなし）・あざやかな色一色のベタ塗りのブロック（影・つや・ふちのない平面。辺が接している同じ色同士は、すき間なくつながって見える。L 字の内側の角も段差なし）。
  文字とボタンは濃い紺。盤面・手駒の描き方は宝石と同じで、`board-themes.css` の色と影だけを変える（結果のシェア画像は宝石と同じ）。
- **3D**（`src/ui/cube3d.js`・`cube3d-math.js`）: ブロック 1 個ずつが**角を少し丸めたガラスの立方体**。本物の 3D エンジン（three.js。WebGL2）で描き、
  - **板の外形の地図は CPU で計算**（`plateFieldData`。半精度のテクスチャにして渡す）。前は GPU のシェーダーで多角形の内外を判定していたが、一部の Android で狂い、板が画面いっぱいに広がったため
  - **同じ色はつながる**: 辺どうしで隣り合う同じ色の立方体は、すき間を埋め、つながった側の角を丸めず、境目の面も描かない（光は境目で曲がらず・色づかず、隣のガラスの中をそのまま進む）。盤面にマスごとのくぼみ（溝）は無く真っ平なので、継ぎ目の線は出ない（盤面そのものにマスのくぼみは無く、真っ平）。
    影・光の地図（コースティクス）・立方体の真下の地図も、つながった塊をひとつの箱として扱う（すき間の影や角の光の線が出ない。`causJoins`）。
    つなぐかどうかは毎フレーム、いま描いている位置で決める（`cubeJoins`）ので、そろって滑っている間もつながったまま
  - **影**は照らす光より真上寄りの光（`SHADOW_DIR`）で落とし、足もとから 3 割ほどだけ斜めに出す（隣の空いたくぼみにぴったり収まって、ブロックがあるように見えないように）
  盤面を**少し下から見上げる**角度（盤面の中心を 20° 見上げる。上の方の立方体ほど下の面が大きく見える）。動画映えのため、ガラスの見え方は画素ごとに光の通り道を計算して決める:
  - **反射**: 入る角度で強さが変わる（フレネルの式。真正面 4%、浅い角度ほど強い）。角の丸い所がスタジオの照明を細く映して光る
  - **屈折**: 屈折率 1.52（クラウンガラス）で曲がって中に入り、出口の面で曲がって出る。出た光の先にある盤面（くぼみ・光）が、ずれて見える
  - **中での反射・全反射**: 出口の面で一部は中へ反射し、角度が浅いと全部戻る。3 回まで追いかける（ふちが暗く・鏡のように見えるガラスらしさ）
  - **色**: 通る距離が長いほど濃くなる（ベール・ランベルトの法則。一辺を通ったときに残る光の割合を色ごとに決めてある）。厚いふちほど深い色
  - **分光**: 出口で赤・緑・青の曲がり方を少しずらす（ふちに虹色がにじむ）
  - **コースティクス**: 左上の光がガラスを通って盤面に落ちる色の光（通る距離で色づき、角の丸みで曲げられた光がふちの内側に集まる）と、接地の影。
    空いたマスに隣の立方体の色の光が落ち、立方体の中から盤面の光が透けて、内側から光って見える
  - **隣のガラス**: 横の面から抜けた光は、隣のマスの立方体の色で色づく（並んだガラスどうしが透けて見える）
  - 照明はスタジオ（左上の大きなソフトボックス・左右の細いストリップライト・手前の面光源・床の照り返し・小さな太陽）を、方向の関数で描いた環境。
    明るさは 1 より大きく持ち（HDR）、明るい所だけを広げてにじませ（ブルーム）、最後に色を保つトーンマッピング（Khronos PBR Neutral）で画面の色にする
  - 盤面はすりガラスの板（彫り込みのマス・丸く面取りしたふち・下から見える板の厚み・奥の壁に落ちるやわらかい影・スポットライトの当たり方のむら）
- **3D の背景**: 明るい青（`#3a6adf` / `#4479f2`）から始まり、通常デザインと同じくプレイ・コンボ・大きな連鎖・全消し・新記録に合わせて色が変わる。背景の色と変化の長さを `Ambient` から受け取り、ガラス越しの背景と手駒の後ろの光もなめらかに変える。変化が終わったら背景のための連続描画は止める。
- **3D の動き**: 置くと、持っていたピースの位置から盤面へ落ちて、つぶれて弾む（ぴったりはさらに大きく）。持っているピースは盤面から少し浮き（立方体 1 個ぶん）、
  動かす向きへ少し傾き、盤面に色付きの影を落とす。溜め・ゴールに入る（小さくなりながら回る）・仮置き（白っぽい淡いガラス）・消える列の予告（ふちが白く光る）・
  発動したラインのマスが光る・全消しの宝石も、2D と同じ時間で 3D で動く。盤面の外（通路）を流れる立方体と手駒は、後ろから光を当てて（暗い背景の上でも）色ガラスの色を見せる。
  かけら・紙吹雪も、同じエンジンで描いたガラスの立方体の絵になる
- **3D と 2D の重なり**: カメラは「シフトレンズ」（視線は盤面に垂直のまま、目だけが下にある）。盤面に平行な面はゆがまないので、
  **立方体の高さのまん中の面が 2D の盤面とまったく同じ位置に写る**（`cube3d-math.js` の `projection`。テストで確認）。そのため、ラインの光・星・ゴール・番号・
  学習モードの枠などの DOM の表示と、ドラッグの当たり判定は 2D のまま合う。2D のブロック・手駒は位置を保ったまま隠し（`html[data-gl="on"]`）、
  canvas が毎フレームその位置を読んで描く（着地・溜め・ゴール・仮置き・マスの光・全消しは `Renderer.view3d` へ知らせる）。弾む・寄る・揺れるも、DOM の値を読んで合わせる
- **3D の重さ**: three.js は 3D を選んだときだけ読み込む（使う部品だけにまとめたもの。約 520KB、gzip で約 130KB。`scripts/build-three.mjs` で作る）。
  **何も動いていない間は描かない**（最後の絵が残る）。学習モードのおすすめで手駒が弾むだけの間は 30 コマ/秒。盤面の外形は一度だけ距離の地図に描いておく。
  描き続けている間のフレームの時間を測り、遅い端末では描く細かさ・MSAA・ブルーム・中での反射の回数・分光を段階的に下げる（GPU を使わない描画では最初から下げる）
- **3D が使えないとき**: WebGL2 が無い・端末が WebGL を取り上げた・シェーダーが動かないときは、宝石の見た目でそのまま遊べる（`html[data-gl="off"]`。
  WebGL が戻ってきたら 3D に戻る）。一時停止の「盤面の種類」の 3D の見本は、開いたときに同じエンジンで描く（使えない端末では選べない）。
  結果のシェア画像も、ゲームと同じ描き方で背景ごと描いた 3D の盤面になる。効果音はガラスと同じ、ガラスのコップの音
- 上: 左上にホーム・リセット、中央にベストスコア（王冠のピル）、右上にランキング・サウンド・一時停止の各ボタン。中央に現在のスコア（ベストスコアも3桁区切り）。
  対戦中はホーム・サウンド・一時停止（CPU だけ）
- 一番下: ロゴ・ゲーム名・遊べる URL（上の「ゲーム名と遊べる場所」）
  - リセットは今のゲームを打ち切って最初から（ゲームオーバー画面の「もう一度」と同じ動き。確認は挟まない）
- 盤面は直角が下に来るよう回転した三角形。上に GOAL、左右の通路にライン番号 1〜8
- 下: 3つのトレイ（枠線も枠の四角も描かない、手駒はできるだけ盤面のマスと同じ大きさで表示。今の盤面に置けない形も、ほかと同じ見た目で表示する）。
  詰んだらゲームオーバー画面の「もう一度」でも再開できる。デバッグパネルは URL に `?debug` を付けたときだけ表示
- フォントは `src/ui/fonts/` に同梱（Nunito / M PLUS Rounded 1c、どちらも SIL OFL）。
  和文は画面で使う文字だけのサブセットなので、**新しい和文を画面に出すときはサブセットを作り直す**
  （`pip install fonttools brotli && python3 scripts/subset-fonts.py`。index.html と src/ui/*.js のコメント以外の和文を足す）
